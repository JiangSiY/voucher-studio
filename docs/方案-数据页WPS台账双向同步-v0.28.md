### 2.1 逐表范围

下表是首批实施口径；字段或权限待补充的表只能按相应的保守路径处理。**拉取**指获取记录用于指定用途，不等于创建凭证；**仅引用**不生成凭证；**仅查重**不生成数据页业务行。首批不做自动补历史、远端更新、删除、墓碑、冲突合并和定时调度。软件侧写回仅允许按 §4.4 接管录入权后手动逐条创建，未接管时保持 WPS 先录、软件只拉。

| 表 | 首批方向、操作与范围 | 分界依据 |
|---|---|---|
| 00 说明 | 说明表，不纳入同步；不拉取、不写回 | 不适用 |
| 01 往来对象 | WPS → 软件，仅引用；按原 ID 保存 `名称`、`类型`，不代建、不写回 | 基础资料，不做日期切分 |
| 02 项目 | WPS → 软件拉取展示和关联；可按 §4.4 手动创建；旧项目可供引用 | 按设计字段 `签约日期`；无签约日期则待核对，不改取并网或完工日 |
| 03 应收 | WPS → 软件拉取展示和关联；可按 §4.4 手动创建；旧应收可供引用 | 按 `日期` 中的约定收款日切分，不取应收确认日或实际到账日 |
| 04 应付 | WPS → 软件拉取展示和关联；可按 §4.4 手动创建；旧应付可供引用 | 按 `日期` 中的约定付款日切分，不以结算日替代；混填或无法证实语义的记录待核对 |
| 05 结算调整 | 首批仅全表查重，不生成业务行、不写回；业务同步延期 | 后续拟用设计字段 `日期` 表示调整生效日；本批查重不分日期 |
| 06 资金流水 | WPS → 软件拉取展示和关联；可按 §4.4 手动创建 | WPS `日期`（W0-04 已见字段）对应软件 `voucher_date`（凭证日期）：收款按实际到账日，付款按实际扣款日；不得取创建或修改时间。无法确认原值符合口径的记录待核对 |
| 07 发票 | 首批仅全表查重，不生成业务行、不写回；业务同步延期 | 后续按设计字段 `开票日期`；本批查重不分日期 |
| 08 电表 | WPS → 软件，仅引用；按 WPS 原记录同步、不代建、不写回；`表号`仅供校验或候选匹配 | 基础资料，不做日期切分 |
| 09 抄表 | WPS → 软件拉取展示和关联；可按 §4.4 手动创建 | 按 WPS `期间`（`YYYY-MM`），`2026-11` 起属新流程；无效期间待核对，不虚构具体凭证日 |
| 10 物料 | WPS → 软件，仅引用；按 WPS 原记录同步、不代建、不写回；`SKU`仅供校验或候选匹配 | 基础资料，不做日期切分 |
| 11 出入库 | WPS → 软件拉取展示和关联；可按 §4.4 手动创建 | 实际出入库业务日，候选字段 `日期`（W0-07 已见字段；业务语义待确认） |

### 2.2 日期和旧资料引用

- 日粒度按业务所在地自然日比较；带时区的到账时间按 `Asia/Shanghai` 转为自然日。缺失、无效、语义未确认的日期保留源记录定位，列入待核对，不用录入日兜底、不跳过、不写回或入账。例：10 月 31 日到账、11 月 2 日补录仍归旧流程；11 月 1 日到账、之后录入归新流程。
- 按 WPS 文件、表、远端记录 ID 拉取并关联原资料。新业务指向旧客户、电表、物料、项目或单据时，先解析原引用再关联，不按主数据创建日截断，不按同名自动代建。缺少、失效或匹配不唯一时显示缺项及来源，进入待核对，不生成无归属账。

### 2.3 显示、关联与正式入账

| 状态 | 判定条件 |
|---|---|
| 数据页已显示 | 拉取记录具备可追溯源 ID，已持久化为台账来源行；区分只读、已同步和待核对。显示不等于生成凭证 |
| 已完成关联 | 日期与必需引用已核验，目标本地记录唯一，且远端记录与本地对象的对应关系已持久化；同一记录重跑复用原关联。仅有远端 ID 或 `wps_links.voucher_id` 为空，不能算凭证已关联 |
| 正式入账 | 仅适用需入账的业务；须按现有财务流程审核，由用户本人确认，并有可追溯的凭证号或入账凭据。同步、回填、导出或生成草稿均不自动入账；确认入口和凭据映射待补充，未补前只允许显示、匹配或待核对，不标为已入账 |

## 3. 数据模型与迁移

### 3.1 表清单

`SCHEMA_WPS` 当前 13 张表（`SCHEMA_VERSION` 保持 4，不 DROP/ALTER 已有表、不清库）：

`wps_links`、`wps_tombstones`、`wps_scans`、`wps_conflicts`、`wps_schema`、`wps_master`、`wps_sync_runs`、`wps_run_changes`、`wps_run_created`、`wps_idempotency_keys`、`wps_record_index`、`wps_write_intents`、`wps_state`。

- `wps_links`：`UNIQUE(sheet_id, record_id)`；`voucher_id` 部分唯一索引；`idempotency_key` 普通索引；`voucher_id` 外键 `ON DELETE CASCADE`。
- `wps_conflicts`：`link_id` 外键 `ON DELETE CASCADE`；`UNIQUE(link_id, field_id)`。
- `wps_run_changes`：`UNIQUE(run_id, link_id, field_id)`；无外键，保留审计。
- `wps_idempotency_keys`：`idempotency_key` 主键、`run_id`、`record_type`、`local_status`（`pending/succeeded/unknown`）、`remote_record_id`、`created_at`。
- `wps_record_index`：`UNIQUE(sheet_id, record_id)`；`idx_wps_index_key(sheet_id,business_key)`、`idx_wps_index_type(sheet_id,record_type)`。
- `wps_write_intents`：`idempotency_key` 唯一；记录 `run_id/batch_id/sequence/sheet_id/record_type/business_key/target_voucher_id/payload_hash/state/remote_record_id/error`；`state` 为 `intent/remote_succeeded/remote_rejected/unknown/linked/pending_backfill/backfill_failed`，请求前落 `intent`。
- `wps_state`：写入 `schema_version=wps-1`。

以上是现有实现，不表示已支持文件级隔离。W2 须补齐文件级命名空间，或将本地同步存储绑定到唯一目标文件并拒绝直接复用至其他文件；副本与生产不得共用索引、关联或待恢复记录。具体落盘设计待补充。

### 3.2 迁移方式

- 方案 A：保持 `SCHEMA_VERSION=4`，`SCHEMA_WPS` 全部 `CREATE TABLE/INDEX IF NOT EXISTS`，在 `schema::init()` 末尾事务内执行；不 bump、不清库。
- 迁移前快照：已有 `vouchers` 数据且 `wps_links` 不存在时，`VACUUM INTO backups/pre-wps-*.db`，保留最近 3 份；失败中止启动。
- 建表失败：回滚，应用报错并停用同步；不得继续调用 WPS。
- 运行期自检：`WpsStore::ensure_schema` 遍历 `WPS_TABLES`，缺表/版本不符返回 `WPS_E_SCHEMA`。

## 4. 预检方案（A 分页全表 + 本地索引）

### 4.1 结论

- **A（唯一预检路径）**：分页全表拉取 + 本地 SQLite 索引，按业务键比对。
- **B（不成立）**：`view_id` 过滤确实生效，但视图条件是静态的，MCP 白名单没有建/改视图工具，无法为任意单号动态建视图；B 只能用于固定范围缩窄。
- **view_id 缩窄**：降级为**未验证优化项**，不作为 G0/G1 门禁依赖；需要验证时只用**已存在的视图**做只读拉取，不在应用内新建/修改视图。
- 09 门与 doc guard 一律 `view_id=None` 整表刷新。

### 4.2 成本与页预算

`page_size=500` 时，W0 记录的页预算：02/03/04 约 2 页、06 约 4 页、09 1 页、11 约 15 页。单轮 02–11 合计约 26 页；MCP 单轮可接受请求数仍无官方数据，靠 W1 实测/429 退避。

### 4.3 创建前检查顺序

- 09：key 校验（0 请求）→ 刷新 09 全表 → `complete=false` 或 `skipped>0` → `WPS_E_09_STALE` → 查索引 → `WPS_E_09_DUPLICATE` → 放行。
- 单号表：key 校验（0 请求）→ 刷新对应表 → 同上 → `WPS_E_DOC_KEY/STALE/DUPLICATE`。
- 两者全程只调用 `dbsheet.list_records`，不发送写请求；doc guard 只查单号重复，**不查主数据引用**。

- 同一创建批次在发请求前校验空键与同表重复业务键；按涉及表各刷新一次（一条分页链、一个 scan），在同一轮索引上检查历史键、跨端匹配与必需引用。任何一项不通过，整批零业务写入；预检只允许本地索引和扫描记录落盘。通过后才进入 §6 的逐条写入，不承诺整批回滚。

### 4.4 历史与跨端查重、录入互斥

- 查重按表扫描完整历史，不按 `2026-11-01` 截断、不传 `view_id`、不依赖 `filter` 查单号。单号表使用 §5 的统一键映射；09 使用原电表记录 ID + 期间。相同字面键在不同表不直接视为同一笔。
- 已有来源关联优先按 `(WPS 文件、表、记录 ID)` 复用；无关联时，单号或复合键只定位候选。唯一候选须再按该表已确认的核对字段验证同一笔（如资金凭证的实际到账日、方向、金额与关联对象，逐表字段及本地映射待补充）。同键但关键字段不符、多条候选、缺键或无法解释的跨端不同号，均转待核对，不自动合并、关联或新建。无候选只有在完整扫描、稳定业务身份、录入互斥都成立时才允许新建；没有可验证的共用业务身份时，该类保持仅拉取。
- **首批默认 WPS 是唯一录入口，软件只拉取。** 软件需要写回时，仅能对已批准的表和明确圈定的业务范围手动启用：由用户本人负责录入权交接，指定唯一录入方，暂停该范围内的 WPS 人工录入及其他写入入口，串行执行软件创建；从预检开始到写入及核对完成前保持互斥。无法确认互斥实际生效，或发现区间内有冲突写入，立即停止写回并对账。进程内运行锁不能约束 WPS 操作人员；锁定范围和权限落实方式待补充，未落实不得启用。W0-06 已证明 09 可以创建重复记录；其他表服务端唯一约束待验证，不作为首批保障。

候选核对最低字段（源侧名称依据台账设计，实施时须映射到已确认的本地字段）：02 项目编号 + 客户 + 签约日期；03 应收单号 + 日期 + 项目 + 对方 + 金额；04 应付单号 + 日期 + 项目 + 对方 + 应付金额；06 流水号 + 日期 + 方向 + 账户 + 金额 + 业务归属；09 电表原 ID + 期间 + 上期/本期读数；11 单号 + 日期 + 仓库 + 原物料 ID + 方向 + 数量。金额按分、数量按约定精度比对，引用按原 ID 比对，不以同名替代。必需字段无本地映射或公式值未稳定时仅待核对，不降低匹配标准。

## 5. 分页拉取与本地索引

- `pull_sheet(client, store, sheet_id, record_type, view_id, page_size)`：`page_size` 上限 500，页上限 1,000；支持 `records`/`data.records`/`data` 数组，坏记录计入 `skipped`，缺 records 数组返回 `WPS_E_PULL_MALFORMED`。
- 远端/解析/offset 不前进：`finish_scan(complete=false)` 后返回 `Ok(report)`；数据库错误返回 `Err`。
- W1 拉取器的结束条件包括空页、`has_more=false`、`total` 到达、短页且非 `has_more=true`；达到页上限必须 `complete=false` + `WPS_E_PULL_MAX_PAGES`。W2 不得仅凭拉取器返回结束判定业务成功；游标、页状态或结束信号矛盾时按 §5.1 判失败。
- 索引键与业务键由 `wps_index::business_key_for` 单一真源生成；字段依据见 `财务工作流/设计/项目台账_v2_设计.md`（02 L92、03 L119、04 L137、05 L159、06 L174、07 L192、08 L197、10 L205、11 L210）。

### 5.1 首次拉取、断点恢复与重跑

1. 以 WPS 文件、表、记录 ID 为来源身份，按轮次暂存本次完整扫描的记录 ID 和关键字段摘要（含日期、业务键、引用）。首次拉取建立逐记录对账清单；每条必须归入「已同步」「已匹配」「待处理」或「按范围仅引用／仅查重／历史只读」，并注明原因。无法取得 ID 的坏行记录页及位置，整轮不通过。同步清单与写入预检使用本轮有效数据，不把旧索引残留当作本轮已见。
2. 分页异常、坏页（含 `skipped>0`）、重复 ID 或检出扫描期间变动使完整性不可确认时，标记未完成，保留上一轮已确认结果和本轮诊断信息，不推进成功检查点、不因本轮未见而删除、不放行写入。WPS 快照、稳定排序或版本一致性能力待验证；在证实前，首批在可确认的暂停改动窗口完成多页扫描，核对逐记录 ID 和关键字段摘要，不以总数相等证明完整。无法确认扫描稳定时只提供待核对结果，不报成功。
3. 断点恢复默认从受影响表的第一页重新扫描，重新核验该轮依赖；没有快照或稳定游标证据，不从旧 offset 续读。不重放未确认的写入。重跑按原来源身份复用已持久化的行和关联；未变更记录零新增，已变更记录只更新允许处理的显示字段或进入冲突待核对，不覆盖已入账数据。以源记录清单和本地逐项结果核对漏项、重复、错配及待处理状态后才可确认本轮完成；有未决记录须单列，不标为全部成功。

实施约束：现有拉取器逐页 upsert，现有业务键查询不按轮次隔离。W2 必须先暂存本轮记录，完整性核验后才发布成功版本；写入预检只查该版本，失败轮或旧版本均不得授权创建。空页仍声明有后续、到达 `total` 仍声明有后续等矛盾信号必须显式判不完整；无可靠一致性证据时不得仅凭两次总数相等放行。

**本章依据**：[`W1/pull.md`](./验收基线/证据/2026-11-19-W1/pull.md) §2–§4；[`W1/pull-index.md`](./验收基线/证据/2026-11-19-W1/pull-index.md) §3–§4；`crates/voucher-core/src/services/wps_pull.rs`、`wps_index.rs`。

## 6. 写入接口与幂等

### 6.1 破坏性变更

- 旧 `create_records(sheet_id, records)` **已删除**，不保留 `#[deprecated]` 包装。
- 新接口以 `KeyedRecord { record, idempotency_key }` 为元素：`create_records(sheet_id, &[KeyedRecord])`；`create_record(sheet_id, record, key)`。缺少 key 的调用无法通过类型构造（另有 `compile_fail` doctest 固定）。
- 写入路径**统一逐条**调用，`build_create_args` 拒绝单次多条；**不调用 WPS 原生批量接口**。
- 仓库内旧签名调用点已全部迁移；无外部调用方（crate 内公共 API，尚无下游 crate）。

### 6.2 幂等语义

- 创建类每条记录一个 UUID，`idempotency_key` 放在 `tools/call` 的 `arguments` 顶层。
- 缺失 key：本地拒绝 `WPS_E_IDEMPOTENCY_MISSING`，0 请求；记录数与 key 数不一致：`WPS_E_IDEMPOTENCY_COUNT_MISMATCH`，0 请求（内部构造器防御）。
- 现有更新接口的 key 可选；首批不调用更新接口。
- 本地 `wps_idempotency_keys` 记录 `pending/succeeded/unknown`、`remote_record_id`；成功回填 remote id。
- **WPS 服务端是否执行 idempotency_key 未验证**；该字段只作客户端追溯/去重标识，不构成服务端幂等保证。
- `pending`/`unknown` 不得自动重试写入；需人工确认。

### 6.3 部分失败

逐条写入：第 1 条成功、第 2 条超时 → 第 1 条 `succeeded`、第 2 条 `unknown`、第 3 条 `not_attempted`；不回滚整批，不自动重试。

### 6.4 写入前留痕与异常恢复

1. 全批预检通过后，每条请求发送前，先持久化写入意图：批次、顺序、目标文件和表、业务键、待关联本地对象、幂等键、请求内容摘要及时间。落盘失败则不发请求。具体存储和事务边界待补充；恢复必须可以定位未结请求，不能换新键绕过待核对状态。
2. 明确成功且完成本地回填才继续下一条。明确拒绝、结果不明、远端成功但本地待回填均停止，后续项标为「未尝试」。只有有证据表明远端明确拒绝且未创建，才归为明确拒绝；超时、断连、响应无法识别、崩溃后未结意图都不能当成未写入。已确认成功的前序记录不回滚，不重发。
3. 开发或运维人员汇集写入意图、安全审计记录、可验证的远端响应与记录 ID、远端记录及关键字段；用户本人核对业务归属并签字确认处置，签字留痕方式待补充。按目标文件和表核对；仅当证据能证明该远端记录确由本次请求创建、业务字段一致且无冲突关联时，才在本地幂等补链并记录核对依据，不再调用创建。业务键唯一命中、字段相同或单次查询无结果，本身都不足以证明来源或未写入。
4. 证据不足则保留待核对，阻止该笔再提交，不自动重发或补链；普通拉取即使遇到同键记录也只能展示候选，不得绕过此限制。只在负责人留痕确认已创建并完成补链，或有独立证据确认未创建且书面批准重新发起后，才解除该笔阻塞；后续未尝试项须按最新状态重新预检，不自动续跑。WPS 服务端是否执行幂等键、能否按键查询均待验证；不能用这些未证实能力替代核对。

**本章依据**：[`实施说明`](./实施说明-WPS幂等-v0.28.md) §2、§3、§5、§6、§7；`crates/voucher-core/src/services/wps.rs`；`docs/实施说明-WPS幂等-v0.28.md` §「方案 §4/§6 写入接口说明」。
