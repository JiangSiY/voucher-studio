# Voucher Studio · Tauri 2 重写开发方案

> 本项目是 `voucher-print`（PySide6 v4.3，凭证整理打印工具）的 Rust + Tauri 2 跨平台重写版本。
> 源项目路径：`d:\开发\voucher-print`（重写期间进入维护模式，只修 bug 不加功能）。
>
> **定稿说明（2026-08-19）**：旧数据不保留。本项目为**完全无包袱的重写**——不做导入工具、不迁移旧库、不兼容旧加密格式。新版空库直接上线。

## 1. 目标与总体判断

- **目标**：macOS 原生可用，安装包从 85MB 降到 10–20MB，摆脱 PyInstaller 误报与打包脆弱问题，获得官方自动更新能力。（原为「Windows + macOS 双平台原生可用」；**自 v0.17.0 起仅支持 macOS**——办公环境已全部转到 macOS，Windows 端维护成本不再值得，见 `docs/开发日志.md` 2026-09-24 条目。）
- **难度评级**：8/10（高）。瓶颈不在 Tauri 2，而在 Rust 语言学习曲线、前端技术栈，以及**打印**与**本地 OCR** 两个生态缺口。
- **周期**：兼职节奏约 6–12 个月；全职可压缩到 5–6 个月。
- **Non-goals**：不做 Linux 版、不做移动端、不做 i18n、不做浏览器分发——防止范围蔓延。

## 2. 四个前置决策（定死，不再反复）

| # | 决策 | 理由 |
|---|------|------|
| 1 | **并行重写，不做渐进迁移** | Python↔Rust 无共享运行时，绞杀者模式需要跨语言桥接，比重写更复杂。v4.3 只修 bug。 |
| 2 | **旧数据不保留，不做导入工具** | 新版空库直接上线：schema 自由设计、加密用 keyring、无迁移无兼容包袱。已拒替代：写 importer 把 v4.3 数据导入新库——维护两套 schema 映射的成本与心智负担，高于重新录入数据的价值。 |
| 3 | **前端选 Vue 3 + Vite + TypeScript**（单向门） | 真实理由：学习曲线最平缓（中文生态好、模板语法对 Python 思维友好）、QSS 双主题经验直接映射为 CSS variables。已拒替代：React（生态最大但心智模型陡、JSX 对新手负担重）、Svelte（包体最小但生态薄、排错参考少）。反转成本：换框架 = 全部页面重写（约 2–3 个月），阶段 4 启动后不许动摇。 |
| 4 | **测试资产当验收标准** | 全部非 GUI 测试的断言语义移植成 `cargo test`（migration 类测试 test_migration / test_migrate_ledger 随旧数据路径退役）；45 项真机验证清单 + 32 个 GUI 测试场景作为新版人工验收清单。**三清单须固化为 `docs/验收基线/` 下的文件（G2 评审门前完成），否则门判定退化为"凭印象"。**（**校正 2026-09-24**：清单二已增至 **47 项**、清单三增至 **36 场景**；计数与文件名的处理约定见阶段 5 门注记。） |

## 3. 现有模块 → 新技术栈映射

基于 v4.3 实际代码（`voucher/` 业务核心 + `gui_qt/` 界面层）逐项核对：

| v4.3 模块 | 文件 | Tauri 2 方案 | 难度 |
|---|---|---|---|
| SQLite 仓储 / UoW | `db/`（connection, schema, unit_of_work） | rusqlite + 显式事务（schema 自由设计） | 中 |
| 数据迁移 | `db/migrations` | **不迁移**（旧数据不保留，整条线删除） | — |
| 业务模型 / 枚举 | `models/`（voucher, attachment, enums, snapshot, export_batch） | serde 结构体 + 枚举 | 低 |
| 云 OCR | `ocr.py`（HTTP API 部分）、`http.py` | reqwest | 低 |
| 本地 OCR | `ocr.py`（rapidocr_onnxruntime） | ort crate + 手写前后处理 | **高** |
| PDF 生成 | `pdf/generator.py`、`pdf/fonts.py`（reportlab + 中文字体注册） | printpdf 或 typst | 中 |
| 图片处理 / 透视矫正 | `imaging.py`（Pillow + opencv-headless） | image + opencv crate | 中 |
| MD5 去重 | `dedup.py` | md5 crate | 低 |
| 命名规则 | `naming.py`、`naming_rules.json` | serde_json | 低 |
| 微信收件夹监听 | ~~`wechat.py`~~ | ~~notify crate + 轮询兜底~~ — **已移除**（v0.7.x，提交 50d2adb；版本演进见 `docs/开发日志.md` §一） | — |
| WebDAV 备份 / 加密 / 定时 | `webdav_backup.py`、`crypto.py`、`scheduler.py` | reqwest / keyring（见下方加密方案）/ tokio-cron | 中 |
| 配置 / 路径 / JSON / 文件锁 | `config.py`、`paths.py`、`jsonio.py`、`file_lock.py` | serde + directories crate | 低 |
| 事件总线 | `events.py` | Tauri event 系统 | 低 |
| 凭证管理核心服务 | `services/voucher_mgr.py` | voucher-core::services（应用心脏） | 中 |
| 导出批次服务 | `services/export.py`（对应 export_batches / export_items 两张表） | voucher-core::services | 中 |
| 搜索服务 | `services/search.py` | voucher-core::services（SQL 语义等价移植） | 中 |
| 报表统计 | `pdf/reports.py` | voucher-core::services + 前端图表 | 中 |
| 平台适配 / 日志 | `platform.py`、`logging_config.py` | tauri-plugin-log + 平台判断 | 低 |
| 30 个界面文件（21 顶层 + 5 widgets + 1 qss + 入口） | `gui_qt/`（workbench, sidebar, list_panel, preview_panel, drop, recovery_window...） | Vue 3 组件重写 | 中（量大） |
| QThread 后台 workers | `gui_qt/workers.py` | tokio 异步 + Tauri 事件推送 | 中（范式转变） |
| 打印链路 | PDF 生成后系统打印 | WebView print / 平台特定代码 | **高** |
| Mica 窗口效果（ctypes hack） | `gui_qt/win_controls.py` 等 | tauri-plugin-window-effects | **低（Tauri 优势）** ——**校正 2026-09-24：Mica 是 Windows 材质，macOS 上不生效（A5 审计实证）；自 v0.17.0 起项目仅 macOS，窗口材质改走 macOS 原生路线（Liquid Glass / NSVisualEffectView）** |
| 自动更新 / 托盘 / 单实例 | 自研 | Tauri 官方插件 | **低（Tauri 优势）** |
| QSS 双主题系统 | `gui_qt/style_manager.py`、`styles/app.qss` | CSS variables + `[data-theme]` | 低（功底直接迁移） |
| 数据导入工具 | importer（v4.3 数据 → 新库） | **不迁移**（已拒替代方案，见决策 2） | — |

**加密方案（P0，2026-08-19 定稿）**：不做 v4.3 Fernet/DPAPI/Keychain 旧格式兼容。敏感凭据（WebDAV 密码、云端 OCR API Key）用 `keyring` crate 存入系统原生凭据库（**macOS 钥匙串 / Keychain**；原句为「Windows 凭据管理器 / macOS Keychain」，自 v0.17.0 起仅 macOS），保持「密钥不明文落盘」约束。备份 zip 为新版自有格式（带版本号清单），恢复能力只针对新版自产备份。

**UI 层红利**：v4.3 手工实现的响应式断点（760px 三档）、accessibleName/Description 无障碍、虚拟滚动、骨架屏，在 Web 栈里是原生能力（media query / aria-* / content-visibility），工作量降一个量级。

## 5. 分阶段计划（12 个月，兼职节奏）

### 阶段 1：学习 + Spike 验证（M1–M2）→ **G1 止损门**
- 学习线：Rust《The Book》前 15 章 + Rustlings；用 Rust 写读 SQLite → 输出 JSON 的小 CLI。TS/Vue 官方交互教程 + Vite 待办清单 SPA。
- **Spike A（M1）**：Tauri 2 窗口 + WebView 打印 API 打印带中文字体的凭证整理单，**在目标平台各验一次**（原文为「Windows + macOS 各验一次」；2026-08-20 Windows 侧通过，macOS 侧因无 Mac 设备挂账，2026-09-23 起 macOS 环境就绪、自动断言已通过、人工样张走查仍挂账——**自 v0.17.0 起仅 macOS**，见 `spikes/print-poc/report.json` 的 `platforms`）。**判定标准（4 项全过才算达标）**：① 中文无豆腐块；② A4 纸张与 @page 边距生效；③ 分页精确（**原设想「每页 4 张卡片」已废弃**，定稿版式为 3 列 × 7 行 = 21 张/页，见 `tests/spike_a_print.rs` 注记与 `services/pdf.rs`）；④ 控制区不出现在打印预览。
- **Spike B（M2）**：ort crate 加载 RapidOCR onnx 模型，对 **≥20 张真实凭证截图**推理，与 Python 版结果比对。**判定阈值**：字段级准确率差异 ≤5%。**✅ 已于 2026-08-19 完成并通过**：ort 2.0.0-rc.13 + PP-OCRv4（det/cls/rec，模型取自 rapidocr_onnxruntime 1.4.4 同源文件，词表内嵌于模型元数据）；24 张合成凭证图（多字体/双列/小字号/±2° 旋转/噪点），**字符级准确率 99.90%、字段级 99.07%、22/24 满分**（报告：`spikes/ocr-poc/report.json`，阈值 95%）。比对对象说明：v4.3 源机不在本机，改为对 ground truth 直接比对——模型同源，验证的是 Rust 侧预处理/后处理的正确性。本地引擎已按此结论集成进应用（`crates/voucher-core/src/services/ocr_local.rs`，与 rapidocr 逐参数对齐）。
- 顺手验证：tauri-plugin-window-effects 的 Mica 效果。**已废止（2026-09-24）**：Mica 为 Windows 材质，macOS 上无效（A5 审计），平台范围收窄后不再适用；窗口材质改走 macOS 原生路线。

**G1 评审门**（OCR 侧 2026-08-19 通过；打印侧 2026-08-20 通过——Spike A 四项判定标准全部程序化验证 + 样张留档，报告 `spikes/print-poc/report.json`。实现路线定稿：printpdf 后端直出，替代原设想的 WebView 打印；macOS 侧待设备按风险表「Spike 结论过期」条目复验）：
| 结果 | 动作 |
|---|---|
| 打印 + OCR 双通过 | 按计划继续 |
| 打印不达标 | 降级：接受系统打印对话框 / 外置 headless Chrome 打印 |
| 本地 OCR 不可行 | ~~降级：v2 只保留云端 OCR~~ → **已排除**：Spike B 实测 99.90%，本地引擎已集成并成为默认 |
| Rust 学习无法推进 | **止损**，回到 PySide6 适配 macOS 路线，沉没成本 2 个月 |

> **阶段 2 现状（2026-09-17）**：✅ 已完成——闭环与凭据往返均有测试覆盖（`tests/voucher_flow.rs`；`tests/keyring_native.rs::keyring_secret_roundtrip`，2026-09-16 起原生凭据用例独立成文件以隔离进程级凭据后端）。

### 阶段 3：业务服务层（M5–M6）→ **G2**

- 全部通过 Tauri commands 暴露为 API。
- **G2 评审门（两条）**：① cargo test 全绿；② 新库跑通「图片导入 → OCR → PDF」闭环。**到这里最难的纯 Rust 部分结束。**

### 阶段 4：前端基座（M6–M7，与阶段 3 尾部重叠）
- Vue 3 + Tauri 壳：侧边栏导航 + 主布局（对应 sidebar.py + workbench 骨架）。
- 设计系统移植：QSS 双主题 → CSS variables + `[data-theme]`；字体/间距/圆角/动画 token 平移，style_manager.py 语义原样保留。**UI 遵循 `voucher-print-ui-scheme` 设计方案的功能约定（凭证卡片三风格、省墨打印布局、无 QR 码）**——视觉语言原定为 Fluent Design（亚克力侧栏、Reveal 光效、#0078D4 主色），**自 v0.17.0 起改为 macOS 原生观感**（系统字体与语义色、材料分层、同心圆角；见 `docs/开发日志.md` 2026-09-24 条目）。
- 760px 断点语义用 media query 重写；aria-* 无障碍基线 + toast 通知（对应 notification_bar）。
- **四个未决决策，本阶段启动前定案**：
  1. **组件库**：手写 vs Naive UI / Element Plus——手写能 1:1 保住 QSS 观感且无依赖风险，组件库开发快但带来通用 SaaS 观感；
  2. **PDF 预览**：preview_panel 是核心页，须定 pdf.js 方案（嵌入方式与版本）；
  3. **状态管理 / 路由**：Pinia + vue-router（默认，除非有反对理由）；
  4. **中文字体策略**：跨平台 font-family 栈，`pdf/fonts.py` 的字体资产是否内嵌前端共用。
- **退出标准**：空壳应用在目标平台运行，导航、主题切换、窗口材质可用。（原文为「双平台运行…Mica 效果可用」；**校正 2026-09-24**：Mica 属 Windows，macOS 侧改为原生材质路线。）

> **阶段 4 现状复核（2026-08-20，随 v0.3.0 后启动收口）**：实际推进方式为「功能缺陷审计驱动」，基座与页面已随历次迭代成型，超出阶段 4 原范围（页面迁移本属阶段 5）。
> - 导航 ✅（侧栏入口 + 设置页 Tab 分区；原为「待处理 / 全部凭证 / 设置」分组导航，2026-10-16 起按用户要求改为**扁平一列**，开合语义改由**整栏收起**承担：侧栏底部「版本行上方那一行」的整行开关 → 56px 纯图标栏，`appearance.sidebarCollapsed` 持久化）；主题切换 ✅（`appearance.theme` 三态 light/dark/system，跟随系统 + 后端持久化，stores/config.ts 统一应用）
> - **Mica 效果 ✅（本次补齐）**：`tauri.conf.json` 窗口 `transparent + windowEffects(mica→acrylic 回退链)`；CSS 侧 body 透明、侧栏叠 `--mica-tint` 半透明着色（兼无效果系统的兜底）、主内容区不透明保可读性；dialog-mask 半透明遮罩透出 Mica 更贴 Fluent 观感

> - **四个未决决策定案**：① 组件库 → **手写**（1:1 保 QSS 观感，无依赖风险，报表图表亦手写 SVG）；② PDF 预览 → **暂不内嵌 pdf.js**：打印中心已具备 HTML 实时预览（随列数/风格联动，覆盖 preview_panel 场景），导出 PDF 用系统程序打开；如后续需要内嵌预览再立项；③ 状态管理/路由 → Pinia + vue-router（hash）；④ 中文字体 → font-family 栈（原为「Segoe UI/PingFang SC/Microsoft YaHei」跨平台三栈；**自 v0.17.0 起为 macOS 单平台栈**：`-apple-system`/`system-ui` + PingFang SC），PDF 字体资产由后端 `find_cjk_font` 独立解析，前后端不共用
> - 退出标准达成情况：**原结论「Windows 侧全绿；macOS 侧与 G2 挂账合并（待 Mac 设备）」——校正 2026-09-24**：Mac 设备与开发/打包环境 2026-09-23 就绪、macOS 自动断言与打包链路已通过（人工走查仍挂账）；平台范围随后收窄为仅 macOS。

### 阶段 5：页面逐页迁移（M7–M9）→ **G3**
从简单到核心排序，每页完成即发布内测构建：
1. help_page → 2. dashboard → 3. **voucher_list_page + list_panel（核心）** → 4. voucher_form_panel → 5. preview_panel → 6. search_panel → 7. export_panel → 8. settings_page + setting_controls → 9. history_page → 10. restore_panel → 11. wechat_watch_panel → 12. rules_editor → 13. scheduler_dlg → 14. **drop（拖放导入）** → 15. **recovery_window（崩溃恢复）**

- **弃迁项**：migrate_panel（旧数据不保留，无迁移场景）。

## 5.5 文档扫描矫正与增强（v0.6 阶段插入）

### 5.5.1 目标与决策定稿

| 决策项 | 定稿 |
|---|---|
| 引入 OpenCV | **是**（opencv-rust **0.100**，绑定 OpenCV 4.10；原计划 0.92，实施时变更，见 5.5.2） |
| 范围（子集） | **倾斜矫正 + 透视矫正 + 自动裁边 + 灰度化 + 自适应二值化**（5 项；去噪与锐化**已于 v0.6.1 实装**，默认关闭） |
| 截图与拍照区分 | **不做来源识别**——按统一流水线处理；区别仅在"输出给谁"：① 截图（来源 = 微信转发/屏幕截图）增强版**只给 OCR**，不用于查看/导出；② 手机拍照（来源 = 拍照/扫描）的增强版**同时给 OCR + PDF 导出**（增强版能显著降低纸面噪点对人眼的干扰） |
| 失败兜底粒度 | **单步失败跳过**——任一步骤异常则跳过该步、记录 warn 日志、流水线继续，**最终仍失败时整条流水回退到原图** |
| 用户可控 | **7 个真开关**（每步独立；中值去噪与 Unsharp 锐化自 v0.6.1 起实装，默认关闭）——原为 5 真开关 + 2 个"v0.6.1 评估中"占位 |

来源区分规则：扩展名 + 启发式
- `image/png` 且文件大小 < 500 KB + 长宽比接近屏幕（4:3 / 16:9 / 9:16 ± 15%）→ 视为**截图**（增强版仅 OCR）
- 其他 → 视为**手机拍照/扫描**（增强版用于 OCR + PDF 导出）
- 规则先按扩展名 + 比例 + 文件大小启发式判断，v0.6.1 可加内容启发式（边缘锐度分析）

### 5.5.3 处理流水线（实装 7 步；原设计 5 步，去噪与锐化于 v0.6.1 补入）

```
原始图
  │
  ├─ 1. 倾斜矫正 deskew（HoughLinesP 找最强水平线 → 旋转到 0°）
  ├─ 2. 透视矫正 dewarp（findContours + approxPolyDP 找四边形 → getPerspectiveTransform）
  ├─ 3. 自动裁边 autocrop（沿四边形外扩 5% 边距裁剪）
  ├─ 4. 中值去噪 denoise_median（v0.6.1 补入，默认关闭）
  ├─ 5. Unsharp 锐化 unsharp_mask（v0.6.1 补入，默认关闭）
  ├─ 6. 灰度化 to_grayscale（BGR→GRAY）
  └─ 7. 自适应二值化 binarize_sauvola（原设计 Sauvola；实装为 OpenCV adaptiveThreshold(GAUSSIAN_C, 31, 10)）

  ↓ 失败兜底：任一步异常 → 跳过该步、保留前一步结果、最终失败回退原图
  ↓ 输出：增强图（仅 OCR 用 或 OCR+PDF 双用）+ 缓存到 attachments/<id>.enhanced.jpg
```

### 5.5.14 B 步实装报告（2026-08-21）

#### (1) 实装范围

B 批按计划 5.5.11 落地，**全 5 步走 OpenCV 路径**（无 imageproc 依赖，见 5.5.2 决策变更）：

| 步骤 | 文件 | 函数 | OpenCV API |
|---|---|---|---|

| 5. 自适应二值化 | `enhance_pixel.rs` | `binarize_sauvola` | `adaptiveThreshold(GAUSSIAN_C, block=31, C=10)` |

任一 Ok 替换 current；任一 Err 保留 current，继续下一步
最终输出 PipelineOutput { mat_color（步骤 1-3 后彩色）, mat_ocr（步骤 4-5 后二值）, trace }

#### (2) 环境固化

- **OpenCV 4.10 源码编译**（brew 现供 5.x / `opencv@4` 4.14，与代码依赖的 4.10 API 面不兼容）→ 装到 `~/.local/opencv-4.10`，`PKG_CONFIG_PATH` 指向其 `lib/pkgconfig`

- **cargo PATH**：`. "$HOME/.cargo/env"`（harness shell 会覆盖 PATH）

判据：`pkg-config --modversion opencv4` 必须打印 `4.10.0`。完整前置与打包步骤见 `README.md`「环境要求 / 构建」与 `AGENTS.md` 的 macOS 段。

## 6. 贯穿性原则

- **两线作战是大忌**：重写期间 v4.3 只修 bug 不加功能。
- **永远绿色**：每阶段结束打 tag，保证可构建可运行。宁可功能少但能跑。
- **学习时间已入账**：M1–M2 产出低是计划内的，不要因焦虑跳过 Spike。
- **数据是生命线**：旧数据不保留意味着**无旧库兜底**——上线首日对数据目录做双备份 + 恢复演练；此后定期自动备份；文件锁防并发写。备份纪律是新版的唯一安全网。
