### 1.2 为什么会出现「表格右下角重叠」——结构性成因（含实测）

**版面常量**（`crates/voucher-core/src/services/pdf.rs`）：

| 常量 | 值 | 位置 |
|---|---|---|
| 页面 / 边距 / 页眉 / 页脚 | A4 210×297mm / 10mm / 16mm / 8mm | `pdf.rs:68-72` |
| 日报表格行高 | 省纸 **5.5mm**、账本式 **6.2mm** | `pdf.rs:220,196` |
| 表头行高 | 5.5mm | `pdf.rs:198` |
| **列宽：编号 / 摘要 / 对方账户** | **45 / 70 / 50 mm** | `pdf.rs:204-206` |
| 金额 | **右对齐到右页边（200mm），不预留列宽** | `pdf.rs:885-901`（`right_x`）、`816-901`（`draw_table_row`） |
| 字号（当前） | 表头 8.0pt、正文 8.5pt、金额 9.0pt、合计行 9.0pt、页脚 7.5pt、标题 14pt | `pdf.rs:789,816-901,920` |
| 每页行数 | 省纸：首页 32 / 后续 38；账本式：34 | `pdf.rs:221-222,202` |
| 图片页 | 竖票 3×3（9/页）、横票 2×2（4/页）；caption 6.5pt（省纸）/7.0pt（账本式） | `pdf.rs:226-228,242-250` |

**核心结论（这就是"右下角重叠"的机制）**：

> 可用宽 = 200 − 10 = **190mm**，而三列固定占 45+70+50 = **165mm**，**金额只剩 25mm**。
> 金额靠"右对齐到页边"挤在那里，**没有自己的列宽**——只要金额位数变长**或字号变大**，它就会压进「对方账户」列。

**宽度模型的算术**（`text_width_mm`，`pdf.rs:1077-1095`：ASCII 记 0.55 字宽、其余记 1.0；1pt = 0.3528mm）：

| 文本 | 8.5pt | 9pt | **12pt（小四）** |
|---|---|---|---|
| `20260820-001` | 19.8mm | 21.0mm | **27.9mm** |
| `八月办公用品采购第1批，含打印纸、墨盒与装订夹`（24 汉字） | **67.6mm** | 71.6mm | **95.5mm** |
| `文一办公用品店` | 21.0mm | 22.2mm | 29.6mm |
| `￥412.84` | 12.9mm | 13.7mm | 18.2mm |
| `￥12,345,678.90` | 24.4mm | 25.9mm | **34.5mm** |

**实测**（用 `pypdf 6.15.0` 读今天生成的《凭证汇总表》样张 `spikes/print-poc/sample-daily-report.pdf`，2026-08-20 合成数据 5 张）：

- 表格行距 **5.5mm**（基线 67.1 / 72.6 / 78.1 / 83.6 / 89.1mm）；合计行 96.4mm；页脚 290.0mm（远离表格，纵向不冲突）；
- **金额右端正好压在 200.0mm**（右页边）——即"右下角"那列贴着边界；
- 24 汉字的摘要在 8.5pt 下已占 **67.6mm ≈ 摘要列上限 68mm**（`TCOL_DESC − 2`）——**已经贴顶**，再多两个字就被 `truncate_chars` 截断。

**→ 因此：只把字号放大到小四而不重排列宽，重叠只会更严重。字号、行高、列宽、每页行数必须作为一组参数一起重算**——这是本方案的技术主线。

### 1.3 三个候选版式（**需要你选一个**：§4 T1）

字号口径先对齐：**小四 = 12pt**（四号 14pt、五号 10.5pt、小五 9pt）；现在的正文 8.5pt 比小五还小。

| | 版式 | 列宽（编号/摘要/对方/**金额预留**） | 行高 | 每页行数 | 摘要容量 | 代价 |
|---|---|---|---|---|---|---|
| **A1（推荐）** | 纵向 A4，摘要超宽则**换行成两行** | 42 / 70 / 42 / **36** | 8mm（两行行 12mm） | 首页 ~25 / 后续 ~28 | 单行 16.5 字，两行 **33 字** | 页数比现在多 ~30% |
| **A2** | 纵向 A4，摘要**单行截断** | 42 / 74 / 38 / **36** | 8mm | 首页 ~25 / 后续 ~28 | 单行 17 字（超出显示「…」） | 摘要看不全，伤"方便核对" |
| **A3** | **横向 A4**（297×210） | 42 / **130** / 45 / **40** | 8mm | ~19 | **30 字** | 每页张数少、装订更厚 |

（12pt 下：编号列 42mm 可放 19 个 ASCII，`20260820-001` 要 27.9mm ✓；对方账户 42mm 可放 ~10 汉字；**金额必须预留 ≥36mm**，否则又会压列。）

### 1.4 「不重叠」怎么保证（做成可测，而不是靠眼睛）

1. **几何不变量单元测试**（Rust 纯函数层，最便宜也最稳）：
   ① 任意金额的估算宽度 ≤ 金额列预留宽 − 2mm；② 行高 ≥ 字号 × 1.4；③ 文本右端 ≤ 右页边（200mm）；④ `每页行数 × 行高 + 表头 + 合计行 + 页脚 ≤ 可用高度`。
2. **样张探针**：用固定合成数据生成一份日报 PDF（`spikes/print-poc/` 已有先例），再用脚本读回文本坐标断言（我已验证 `pypdf` 能读出我们 PDF 的文本位置；注意它每段只稳定返回首个文本块，探针按"每行首段"取样）。
3. **真机目视一次**（打印或 PDF 预览），重点盯三处：**右下角「金额 / 合计」与「对方账户」列**、最后一行行底细线与合计线、页脚。

### 1.5 功能取舍（**需要你选**：§4 T2，可多选）

用户已明确「其余用不到」，但每一项的删除都有连带代价，列清楚再让你勾：

| 候选删除项 | 删掉的代价（必须一起处理） |
|---|---|
| **单份 PDF**（非按天） | 与日报共用 `export_pdf`；删掉后「卡片风格 / 每行列数」也随之失去意义（那套只服务卡片版式） |
| **Excel(xlsx) 导出** | 导出历史页的「格式」列少一种；`export_coverage` 的格式分布统计要改；`rust_xlsxwriter` 依赖可下线（少一个大依赖） |
| **CSV 导出** | 同上（两者共用 `export_table`） |
| **年度汇总报表** | 洞察页那一个按钮 + `export_yearly_report` 命令（约 250 行版面代码）可下线 |
| **卡片风格 / 每行列数** | 只服务"单份 PDF"；删单份后它们自然消失 |
| **账本式日报模板** | 设置页少一档（但它是"存档版式"，若你要长期归档可能想留） |
| **附带附件图片页** | 日报里就没有票据图片了（只留汇总表）——**建议保留**，你要不要留请明确 |
| **打印优先增强版图片** | 设置页少一项；扫描件打印清晰度会退回原图 |
| **导出历史页的格式列 / 批次反查** | 与你现在的日报流无关，但它是"未导出"待办口径的依据——**建议保留** |

### 1.6 打印部分验收（v2 定稿后落成用例）

1. 日报表格正文字号 ≥ **12pt**（小四），表头与合计行同档或更大；
2. 任意一行的「金额」右端 ≤ 200mm，且**左端不与「对方账户」列文字重叠**（不变量测试 + 样张探针双保险）；
3. 行距 ≥ 字号 × 1.4，行与行不重叠；行底细线不与文字相碰；
4. 合计行与最后一行、合计行与页脚之间都有 ≥ 3mm 净空；
5. 每页行数按新几何生效（首页/后续可不同），页脚「第 x / y 页」总数正确；
6. 摘要按选定版式处理（换行 / 截断）后**不越列**，且截断处可见「…」；
7. 图片页：图片不越格、caption 不压图、caption 不越页脚；
8. 打印同一天两次，输出一致（幂等）；导出历史里该批次张数口径不变。

## 第二部分 · 凭证关联与佐证（摘要，详版见链接）

- **推荐路线**：**P1 关联表**（多对多 + 关系类型 + 说明文本）＋ **P1′ 允许「无图凭证」**（说明/备忘/法定「原始凭证分割单」，成本极低，建议同批）→ **P2 打印/导出带佐证**（主件页 + **附件清单页**按关系类型分类小计 + 附件逐页；导出「关联清单」）→ **P3 事项组**（作为关联表的一种关系类型）。
- **不动**「一张图片就是一张凭证」（三处闸门：DB 唯一索引 + ingestion 两处校验 + 内容 MD5）。
- **与打印的交叉点**：P2 的「附件清单页 / 关联清单」正好落在本稿第一部分的日报版式里——**所以打印版式定稿时要为它留位**（A1/A3 都留得下，A2 因为摘要截断会挤）。
- **不确定项**：见 §4 L1–L7。

## 第五部分 · 明确不做（除非你另行要求）

- 不放宽「一图一凭证」（一凭证多图）；
- **不做带金额的关联**（核销/冲销/借款抵扣）——第一版只做纯语义关系（Sage 的余额不变量那类留到真需要时）；
- 不做复式记账语义、不改编号规则、不改去重与对账口径；
- 不把关联记录排进日报正文表格（改用独立的「附件清单页」，绕开行业公认难题）；
- 本稿阶段**不写任何代码**。
