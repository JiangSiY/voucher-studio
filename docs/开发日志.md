# 开发日志

> **定位**：本文件是 voucher-studio 的**过程与证据档案**——只追加（末尾"当前挂账"一节除外，它随状态更新）。
> **与其它文档的分工**：`docs/开发方案.md` = 计划与规范（活文档，跟随代码实况更新）；本文件 = 发生过什么、凭什么证据、留下什么；`docs/voucher-studio-{health-check,project-analysis,fix-status}*` = **时点快照**（正文永不改，只在头部加校正注记）。
> **维护约定（强制）**：出现以下任一时机，必须在本文件追加一条 —— ① 版本号 bump；② 过一次门（G1–G4）；③ 完成一次审计/体检；④ CI 修复或 CI 规则变更；⑤ 任何"改动源码"的批次收口。
> **条目字段（7 项，缺项写"无"）**：日期 / 版本·门 / 触发 / 关键提交 / 门禁证据 / 产出物 / 遗留与挂账。
> **重建条目**：`v0.1.0–v0.14.0` 段为 2026-09-17 依 tag、提交历史与既有报告**回溯重建**，每条标注依据来源；它们不是当时的即时记录，细节以 `git log` 与对应报告为准。
> **平台范围**：自 **v0.17.0（2026-09-24）** 起本项目**仅支持 macOS**，Windows 端已移除。本文件 v0.17.0 之前的条目中所有 Windows 相关表述（NSIS/MSI、WebView2、MSVC、`%APPDATA%`、`activate-dev.ps1`、PowerShell/UIA 走查等）**保留原貌，是当时的实况记录**，不随平台收窄改写。

### 2026-10-09 · OCR 自动填写：三字段收窄 + 置信度门控（准确度方案①，金额最严）

- **背景**：OCR 提准确度方案（2026-10-08 定稿）推荐顺序 ②评测集 → ①门控 → ③换模型 → ④版式模板。第二步落地「宁空勿错」：
  识别层 v5 起就算好 高/中/低 三档字段置信度且前端有对应徽标，但自动填单（`apply_fields`）一直没读它（设计意图只写在注释里）
- **收窄**：只自动填 **日期 / 金额 / 对方账户** 三字段；**摘要永远人工填写**（删两处「对方/商家 → 摘要」兜底写入）
- **门控**：`ocr_fields::should_autofill(conf, strict)`——金额 strict，**只填 High**（大写互验一致或多标签多数互验升级后才算）；
  日期/对方 非 strict，Medium 及以上填；Low 与 None 一律不填（留识别结果卡人工「填入」通道）
- **互验补强**：大写金额互验（壹佰壹拾叁元整 ↔ 小写）从版面路径**扩展到纯文本路径**——两路径共用 `ocr_fields::parse_uppercase_amount`；
  一致 → High，不一致 → 丢弃金额（其一必被读错）。顺手修了原解析器潜伏缺陷：`find('元')` 的**字节下标当字符数用**（`skip/take` 混用），
  导致纯文本路径下角分（X角Y分）永远解析不出——此前无用例覆盖，本批以「伍元叁角」用例锁定
- **纯文本路径补标档**：无版面时按来源标置信度（金额：标签 Medium / 唯一兜底 Low；对方：标签 Medium / 商家回退沿用商家档；
