## 0. 结论摘要

| 维度 | 评级 | 一句话 |
|---|---|---|
| 设计令牌体系 | **B** | 三层令牌与语义命名已立住，但**组件层没跟上**：字号 0 处、控件高 13 处用令牌，其余全是字面量 |
| 字号一致性 / 可读性 | **D** | 11 种字号值、18 个低于 13px 下限、约 2/3 文字不随「界面字号」档位缩放 |
| 视觉一致性 | **C** | 新旧两套语言并存：macOS 蓝 vs 残留 Fluent 蓝 + 靛紫渐变；设置页内联样式自成体系 |
| 状态覆盖（加载/空/错） | **C−** | 空态 6/11 页、**加载骨架 0 处**、页面级错误态 0 处 |
| 维护健康度 | **C** | `base.css` 2030 行里约 1400 行是零引用死样式；全仓 234 处内联 `style` |
| IA / 信息架构 | **B+** | 一列九入口、双行列表 + 右栏唯一编辑器、吸顶筛选——结构是对的，问题在视觉落地 |

**最该先修的一件事**：字号双轨。它同时解释了三类现象——"字看起来还是偏小"、切换字号档位后某些地方没变、以及设置页与主界面观感割裂。

## 1. P0：影响可读性与功能承诺

### 1.1 字号双轨：令牌与硬编码各占一半，「界面字号」档位实际只改了一半界面

**证据（可复现）**

```bash
# 令牌引用（font-size 走 --type-*）
grep -rn 'font: var(--type-' src --include='*.vue' --include='*.css' | wc -l   # 83
# 字面量（不随 --font-scale 缩放）
grep -rn 'font-size: [0-9.]*px' src --include='*.vue' --include='*.css' | wc -l  # 159
```

`base.css` 里出现 **11 种**字号值：`9.2 / 10.3 / 11 / 11.5 / 12.6 / 13.8 / 14.9 / 15 / 16 / 16.1 / 20px`。
其中多数是"已手工乘过 1.15"的产物（13×1.15≈14.9、12×1.15≈13.8、14×1.15≈16.1、10×1.15≈11.5…），
说明它们诞生于"默认大字"时期，**没有收敛进 `--type-*`**：

| 位置 | 现值 | 规范应为（默认档 1.15） |
|---|---|---|
| `base.css:23` body | `16.1px` | `--type-body` = 15×1.15 = **17.25px** |
| `base.css:163` `.sidebar-nav a` | `14.9px` | 正文级 17.25 / 至少 caption 14.95 |
| `base.css` `.dtable td` | `14.9px` | 正文级 17.25 |
| `base.css` `.dtable th` | `13.8px` | caption 14.95 |
| `base.css:398/422` 等标题 | `16.1 / 12.6px` | title 19.55 / caption 14.95 |
| `settings/EnhanceTab.vue:228-239/283/488` | 内联 `font-size: 13px / 12px` | 不可内联；应走令牌 |

**后果**

1. 设置里把字号档从「大(1.15)」切到「标准(1.0)」或「更大(1.3)」时，**只有约 1/3 的文字跟着变**，
   于是层级反转或溢出：例如侧栏仍是 14.9px 而正文变 15px——侧栏比正文还"重"。
2. 默认档下正文 16.1px **低于规范写死的 17.25px**（§0.6「正文 15px 起」），
   与用户 2026-09-24 明确提出的「字号要大一些」相比仍偏保守。
3. 评审时无法用"改一个令牌"校准全局——每次都要逐处找。

**修法（1 批可完成）**

- 建立**唯一映射**：`9.2/10.3/11/11.5 → --type-caption(或新增 --type-micro 13px)`、
  `12.6/13.8 → --type-caption`、`14.9/15/16.1/16 → --type-body`、`20 → --type-title`；
- `body { font: var(--type-body) }`；
- 新增契约：**`src` 内 `font-size: [0-9]px` 字面量必须为 0**（tokenContract 扩展，防回流）；
- 三档各截一张真机图验收（标准/大/更大）。

### 1.2 低于可读下限的字号出现在真实界面

| 位置 | 字号 | 用途 | 是否在用 |
|---|---|---|---|
| `base.css:698` `.list-thumb-source` | **9.2px** | 缩略图"来源"角标 | 旧列表遗留（零引用） |
| `base.css:978` `.appendix-badge` | **10.3px** | 打印中心"已增强"角标 | **在用**（`PrintCenterPage.vue:441`） |
| `base.css` `.sidebar-nav .nav-badge` | **11px** | 侧栏徽标数字 | **在用** |
| `base.css:1278` `.att-enhanced-badge` | **11.5px** | 编辑器"已增强"角标 | **在用** |
| `base.css:1356` `.att-compare-tag` | **11.5px** | 对比模式 A/B 标签 | **在用** |

规范 §0.6 是硬约束（辅助文字 13px 起、可读性优先于信息密度），这 5 处全部越线；
其中 3 处是**功能性状态标识**（增强/来源/对比），越小越容易误读。

**修法**：角标统一 `--type-caption`（13×scale）+ 允许两行；缩略图角标改图标或 tooltip 承载。

### 1.3 规范自身有三处矛盾，导致实现与评审都"没有唯一答案"

| 矛盾 | 位置 | 影响 |
|---|---|---|
| 空状态说明文字：**11px** vs **13px 起** | §1.5 空状态行 vs §0.6/§1.3 | 实装是 14.9px（`base.css` `.empty-state .es-desc`）——实装更合规，**规范该改** |
| 分段控件高 **24** vs 令牌 **26**（`--control-h-sm`） | §1.5 vs tokens.css:74 | 「状态/收支方向」分段高度无唯一值 |
| `--r-8: var(--radius-panel)` 名字是 8、值是 12 | tokens.css:142 | 旧别名名不符实，后来者按名字用会拿到 12px |

**修法**：以实装为准改写规范三处（保留「（原 X，自 v0.23 起改为 Y）」），并在 tokenContract 里锁
「分段高 = --control-h-sm」。

### 1.4 控件高度与字号不同步（字号档放大后按钮不变大）

```bash
grep -rn 'height: var(--control-h-' src --include='*.vue' --include='*.css' | wc -l  # 13
grep -rn 'height: [0-9]*px' src --include='*.vue' --include='*.css' | wc -l          # 32
```

字号档位同时驱动 `--type-*` 与 `--control-h-*`（tokens.css:73-76），但控件高有 32 处写死 →
「更大」档下文字 19.55px 塞进 32px 高按钮，或反之「标准」档按钮显得虚胖。
**修法**：合并进 1.1 的收编批次，控件高一律 `--control-h-*`。

## 2. P1：视觉一致性

### 2.1 旧视觉语言残留：靛紫渐变与 Fluent 蓝

- **靛紫渐变** `linear-gradient(135deg,#6366f1,#8b5cf6)` ×3：`base.css:702`（旧列表来源角标，死）、
  `base.css:1278`（编辑器"已增强"角标，**活跃**）、`base.css:1366`（对比模式左侧标签，**活跃**）。
  与规范 §1.6 的 macOS 蓝 `#0a84ff` 体系无任何关系——在编辑器里是"突然出现的外来色"。
- **Fluent 蓝 `#0078d4`** ×3：`base.css:1045/1051/1065`（`.vcard*` 已下线卡片版式，死）、
  `CropDialog.vue:341/350`（`var(--accent, #0078d4)` 的 fallback，无害但暴露残留）。
- **硬编码灰阶 33 种**（`#e1e1e1` / `#6e6e6e` / `#1f1f1f` / `#8e8e8e` / `#606060` …）绕过
  `--label-*` / `--separator`：这些元素在深色主题下不会变，也无法被 `prefers-contrast: more` 提升。

**修法**：紫渐变 → `--accent`（或 `--bg-selection` + `--accent` 文字）；灰阶逐处换成语义令牌；
所有 `var(--accent, #0078d4)` 的 fallback 删除（令牌必有定义，tokenContract 已保证）。

### 2.2 约 1400 行死样式（`base.css` 共 2030 行）

**证据**：50 个 `base.css` 类名在 `src/**/*.vue|ts` 中零引用（脚本见审计附件命令），其中成片的是：

| 家族 | 行号 | 说明 |
|---|---|---|
| `.vcard* / .vcl-* / .vh / .vb / .vv / .vinfo / .vnote / .vcode` | `base.css:982-1150`（约 170 行） | **v0.22 已下线的卡片版式**（规范 §5「已下线」） |
| `.card / .card-body / .card-header` | `base.css:247-270` | 旧仪表盘卡片，零引用 |
| `.fchip / .filter-chips` | base.css（散布） | 已被 `MultiSelect` 筛选取代 |
| `.dtable .col-check/.col-ops/.list-thumb*/.cell-*` | base.css:600-1000 段落 | 旧列表实现；LibraryPage 已改用 `.rows` 列表 |
| `.nav-group-badge` | 侧栏段落 | 分组标题删除后的遗留 |

**为什么算审美问题**：不是"文件大了"，而是①评审/新人会把死类当现行规范模仿；
②死类里的颜色/字号（`#0078d4`、`9.2px`、白底 `#fff`）会污染 grep 与视觉回归；
③旧类与现存类同名不同义时（`.cell-*` vs `.rows`）极易改错。
**修法**：一次删除 + `base.css` 加"类名零引用"契约（脚本可复用本次审计的检测方法）。

### 2.3 图标尺寸 8 档

```bash
grep -rho 'size="[0-9]*"' src --include='*.vue' | sort | uniq -c | sort -rn
# 14×31  15×22  18×13  13×6  16×5  12×5  17×4  42×3（空状态）
```

12/13/14/15/16/17 六种"小图标"混用（甚至 14 与 15 相邻出现），光学尺寸不齐；
macOS 的惯例是 4 档左右。**修法**：枚举收敛为 `12(行内) / 14(常规) / 16(工具栏) / 18(侧栏) / 42(空状态)`，
加契约断言 `FluentIcon :size` 只能取枚举值。

### 2.4 间距与圆角节奏漂移

- 间距（`padding/margin/gap` 的 px 值频次）：`8×56 / 6×40 / 4×28 / 2×27 / 12×24 / 16×23 / 10×21 / 13×10 / 3×9 / 1×7 / 24×6 / 14×5 / 5×3 / 28×2`。
  4px 基数之外混入 **6/10/13/14/5/3/1px**，尤其 13px 与 14px 相邻使用——视觉上"对齐不齐"的根源。
- 圆角：`6×14 / 4×11 / 2×7 / 8×7 / 50%×6 / 3×3 / 100px×2 / 5×2 / 10×2 / 999px×2`。
  规范只给 4/6/12（+toast 10）；**2/3/5/8px 不在尺规内**，且同心圆角原则（子 = 父 − 内边距）未被执行。
- **修法**：把 `--s-*` 之外出现的值列白名单（`2px` 允许用于双行列表行内微间距），
  13/14/5/3px 归到最近档；圆角统一 4/6/12，删 2/3/5/8。

### 2.5 设置页像"另一个应用"

- `EnhanceTab.vue` 一个文件 **24 处字号字面量 + 内联 `style` 写法**（228-239、283、488 行）；
  `BackupTab.vue` 10 处。主界面已全面令牌化（LibraryPage 列表/编辑器都是 `font: var(--type-*)`），
  设置页却停留在"内联字号 + 局部类名"的旧时代 → 同一产品两种观感。
- **修法**：设置页控件统一复用 `.btn / .input / .toggle / .segmented`，字号走令牌；
  在 tokenContract 里加"内联 `style` 含 `font-size` 即失败"。

### 2.6 内联 style 共 234 处（主题/字号/窄窗都管不到）

典型：`App.vue:229-245`（恢复提示弹层整段内联样式，字号 13px、gap 8px、margin 12px）、
`LibraryPage.vue:706-729`（筛选输入框 `style="max-width:160px"`）、`EnhanceTab` 全文。
历史上 `.cell-ellipsis` 就因为"内联样式优先级高于媒体查询"改过一次类——教训已写在 `base.css:1991`。
**修法**：迁移到 scoped CSS / 全局类，内联样式归零（允许 `v-show` 级别的 display 控制）。

### 2.7 加载态没有骨架，只有一行"加载中…"

```bash
grep -rn 'skeleton\|Skeleton' src --include='*.vue' --include='*.css' | wc -l   # 0
grep -n '加载中' src/pages/LibraryPage.vue                                      # 750: <div v-if="loading" class="hint">加载中…</div>
```

规范 §2.2 要求「加载/失败/无数据」三态显式；现在只有文字提示 → 切页瞬间白屏/布局跳动，
观感上比"慢"更糟（用户会怀疑卡死）。**修法**：给列表/右栏/洞察各做一套 3–5 行骨架
（`--bg-selection` 微块 + `--motion-normal` 淡入），失败态给"重试"按钮。

### 2.8 列表行圆角与缩略图裁切

- `LibraryPage.vue`（scoped）`.row { border-radius: var(--radius-panel) }` = **12px**，
  但规范 §1.5 行级圆角是 **6px**（侧栏项 6）；56px 高的双行列表用 12px 显得"泡泡"，
  hover 底色块也比 macOS 列表重。
- `.row-thumb { 44×56 }` 内 `object-fit: cover`：90% 凭证是长截图（规范 §? 实测中位高宽比 2.21），
  cover 会把长图裁成中间一段——缩略图里"看不到金额和标题"，比留白更难认。
  **修法**：行圆角 6px；缩略图改 `object-fit: contain` + 点状底纹（或按 10/22 竖框）。

## 3. P2：细节与工程审美

1. **动效时长硬编码**：`0.15s×5 / 0.12s×4 / 1.2s×2 / 0.06s / 0.25s / 0.2s`（规范只有 120/200ms）。
   1.2s 这类慢动效在列表/浮层里会拖沓；`prefers-reduced-motion` 有通配兜底，但正常档的节奏不统一。
2. **内容区用了阴影**：`.card` 的 `var(--shadow-2)`（死样式）、`.closing-backup-card` 的 `var(--shadow-28)`；
   规范 §0.2 明确「层级用分隔线+间距，内容区不用阴影」。图片操作控件（`.att-card` 内 6 处硬编码阴影）属可接受的"悬浮件"，但应统一到 `--shadow-menu`。
3. **截断**：`.cell-ellipsis` 类仍在（零引用）；新列表对摘要/对方用 `ellipsis` ✓，金额用 `tabular-nums` 不截断 ✓——
   这一点是**做对的**，但旧表格遗留类会误导后来者。
4. **深色模式**：死样式 `.vcard-clean` 里 `background: #fff; color: #1f1f1f`——若被误复用会在深色下刺眼；
   随死样式一起删即可。活跃界面的深色切换本身未发现破坏（令牌覆盖到位）。
5. **A/B 对比标签**：右侧标签用 `rgba(0,0,0,.55)` 半透明黑、左侧用靛紫渐变——同组两个标签语言不一致，
   建议左右统一为 `--label-primary` 的 65% 黑/白底 + 图标区分。
6. **筛选栏**：`box-shadow: 0 1px 0 var(--separator)` 把"分隔线"写成"阴影"（观感相同但语义错位，
   提高对比度模式下不会变粗）→ 改用 `border-bottom`。
