# Voucher Studio 0.23.0

这一版重做了 **OCR 识别与要素自动填写**：默认改走云端视觉大模型，一次调用同时拿回全文与
日期/对方/金额；云端不可用时自动回退到 **Apple 系统自带的 Vision 引擎**（零下载、完全离线）。
导入也变快了，识别结果卡片上能看到这次到底是哪个引擎认的。

## 本版做了什么

### 新增

- **云端优先识别（DeepSeek 视觉）**：设置页 `OCR → 引擎` 默认「自动」——先走云端
  `deepseek-flash`，一次请求同时返回**整页文本**与**结构化要素**（日期 / 对方 / 金额 / 商户），
  比过去的纯文本规则抽取更稳。识别时图片会上传，按官方价约 **0.003 元/张**。
  引擎可分三档锁定：`自动` / `云端` / `本地`；云端协议也分两种：`DeepSeek`（默认）
  与 `自建 HTTP`（兼容过去的 `{image_base64, model} → {text}` 接口，老配置无需改动）。
- **本地引擎换成 Apple Vision**：不再下载与打包 PP-OCRv5 模型（安装包与数据目录各自小了一截），
  改用 macOS 自带的 `VNRecognizeTextRequest`——中文简体/繁体 + 英文，离线、免安装、免联网。
  实测同一批真实票据，要素命中率与原方案持平，速度快约 3.8 倍（平均 247ms vs 950ms）。
- **导入期识别并发**：云端模式下一次导入多张图会并行识别（3 路），8 张图从约 40 秒降到十几秒；
  回填仍逐张串行，写库不与导入事务争锁。
- **识别来源标签**：详情页图片区的「已识别」旁边直接显示这次是谁认的
  （`DeepSeek` / `云端自建` / `本地`），识别结果卡片上也有完整说明。

### 修复

- **「重新识别」现在会真的重跑**：以前命中过缓存的附件，点重新识别只会拿回上一次的结果
  （提示成功但标签不变、实际什么都没跑）；现在该按钮跳过缓存、按当前设置重跑，并覆盖旧结果。
  换引擎后想重认历史附件，点这个按钮就对了。
- **本地识别的置信度读取错误**：本地引擎曾把 `float` 当 `double` 读，导致所有行的置信度变成垃圾值、
  被阈值整体滤掉（表现为「识别成功但 0 行」）；已修正，并补了端到端回归。
- **流水 / 账户明细页不再误填**：这类多行列表页过去会被按第一行填进金额与对方；现在按行数特征识别出来，
  只保留文本与商户，金额与对方留空由你手填，卡片上有明确提示。

### 维护

- 新增 `ocr_field_cache`（云端结构化要素缓存，换模型各自失效）与版面记录的引擎维度；
  老库升级自动补表/补列，**不动** `SCHEMA_VERSION`、不清库。
- 测试与文档口径：Rust 319 例（172 单元 + 144 集成 + 壳 3）、前端 56 文件 352 例；
  README / 清单一 / 开发日志三处口径与实测一致。

> 更新功能从 0.22.4 起生效。装 0.22.4 或更新的版本，可以在
> `设置 → 通用 → 检查更新` 里直接升到本版。
> 云端识别需要在 `设置 → 密钥管理` 里填一次 DeepSeek API Key；不填也能用（会自动用本地引擎）。

## 安装与校验

本版**未做 Apple 公证**（没有开发者账号签名），首次打开需要：

1. 把 `Voucher Studio.app` 拖进「应用程序」；
2. 右键 → **打开**（或系统设置 → 隐私与安全性 → 仍要打开）；
3. 如果仍提示已损坏或无法验证，执行：
   ```bash
   xattr -dr com.apple.quarantine "/Applications/Voucher Studio.app"
   ```

**自检依赖是否齐全**（本版应当只打印 `@rpath` 与系统框架，没有任何 `/Users/…` 输出）：

```bash
otool -L "/Applications/Voucher Studio.app/Contents/MacOS/voucher-studio" | grep -v @rpath
```

如果这条命令打印出 `/Users/...` 开头的路径，说明装的是旧版（0.22.2 及更早），请下载新版。
