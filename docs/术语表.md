## 一、这东西的全貌

**桌面应用** —— 装在电脑上、双击就开的程序。本项目就是一个桌面应用，只支持 macOS。
**前端（界面）** —— 你看到和点的部分。本项目的界面是用做网页的技术写的（Vue），只是装在了一个应用窗口里。
**后端 / 内核** —— 你看不见的部分，负责算账、识别图片、生成 PDF、备份。本项目内核用 Rust 写。
**Tauri** —— 把"网页界面"和"Rust 内核"组装成一个桌面应用的框架。本项目基于它（版本 2）。
**WebView** —— 系统自带的网页渲染器（macOS 上是 Safari 的内核）。界面其实跑在它里面。
**Rust** —— 内核用的编程语言。特点是"管得严"，很多错误在编译时就拦下，代价是写起来啰嗦。
**TypeScript** —— 界面用的语言（JavaScript 的"带类型版"）。类型=给数据贴标签，写错标签会被工具拦下。
**Vue** —— 界面框架，用"组件"拼页面（一个组件 ≈ 一块界面）。
**SQLite** —— 嵌入式数据库：整个数据库就是**一个文件**。本项目所有凭证数据都在 `voucher.db` 里。
**数据库表** —— 库里的"表格"，每张表存一类东西。本项目 11 张：`vouchers`（凭证）、`attachments`（附件）、`dup_decisions`（重复处置记录）、`export_batches` / `export_items`（导出批次）、`ocr_cache` / `ocr_layouts`（识别结果）、`enhance_hits`（增强使用记录）、`period_locks`（封账）、`snapshots`（快照）、`config`（配置副本）。
**WAL（预写日志 / Write-Ahead Log）** —— SQLite 的"先记账、后誊清"机制：所有改动**先追加到** `voucher.db-wal`，主库不动；读到的是"主库 + 待誊清单"合起来的结果。**当前完整数据 = 主库 + WAL**。
**检查点（checkpoint）** —— 把 WAL 里的改动一次性誊回主库的动作（应用正常退出时或 WAL 攒到一定大小自动发生），誊完 WAL 清空。
**`-shm`（共享内存索引）** —— 放在共享内存里的一张"目录/协调表"，记录 WAL 里哪些页有效、谁在读谁在写。**它不是数据副本**；进程退出通常自动消失。
**为什么不能手工删 `-wal`** —— 删它等于丢掉尚未誊回主库的改动，数据会"退回"到上一次检查点（可能少几张凭证）。这三个文件（`.db` / `-wal` / `-shm`）一律不要手工动。
**VACUUM INTO（备份快照）** —— 把数据库**另存一份整理好的副本**：自动包含 WAL 里的改动、去掉空洞因此更紧凑。这是备份不直接拷文件的原因（直接拷可能拷到"写了一半"的状态）。例：你的快照 219KB，比主库 912KB + WAL 4MB 还小。
**数据目录** —— 应用存放全部数据的地方。本机是 `~/Library/Application Support/VoucherStudio`。
**应用标识（identifier）** —— 应用的身份证号，本项目是 `com.voucherstudio.desktop`。日志目录就是按它命名的。
**日志** —— 程序运行时的记录。本项目在 `~/Library/Logs/com.voucherstudio.desktop/`（**注意**：不在数据目录里；`paths.rs` 的注释写着数据目录下有 `logs/`，那处注释已过期）。
**附件** —— 你导入的原始图片，存在 `attachments/年/月/` 下，按内容哈希命名。
**增强版** —— 增强（去噪/锐化/裁剪）之后的图片，属于**可随时重建的缓存**，不算原始数据。
**快照（备份里的）** —— 数据库文件的一次拷贝（很小，约 200KB）。
**附件包** —— 备份里的图片压缩包（很大，几十 MB）。**快照 + 附件包成对存在**，缺一不可。
**导出** —— 从应用里生成 PDF / Excel / CSV 文件，落在 `exports/`。
**OCR 模型** —— 识别文字用的数据文件，在 `models/`（15MB，来自安装包）。
**单实例锁（`.lock`）** —— 阻止同时开两个窗口改同一个库，避免数据被两边同时写坏。
**会话标记（`.last-session`）** —— 记录"上次是不是正常退出"，异常退出时下次启动会提示恢复。

## 二、一次点击的旅程

**接口（interface）** —— 两层之间"能问什么、能给什么、可能怎么失败"的约定。本项目里它以三种样子出现：① **Rust 函数签名**（命令层↔服务层，编译器检查参数类型）；② **命令名 + JSON**（界面↔命令层，跨语言，编译器管不到，靠 `invoke-contract` 测试守）；③ **数据库表结构**（仓储层↔数据库）。一句话：**实现自由，接口不自由。**

**依赖方向（单向依赖）** —— "上层认识下层、下层不认识上层"。本项目靠两层保证：**编译器**（内核的包里没有 tauri 依赖，写不出反向调用）与 **grep 门禁**（命令层不许直连数据库——这一条类型系统拦不住，只能靠自动检查）。
**回调（依赖倒置）** —— 底层需要"往上说话"时的做法：它定义"我要喊什么"（如 `on_progress: &dyn Fn(usize, usize)`），由上层把一个函数塞进来。底层只管喊，不知道谁在听——信息往上流，依赖方向不变。
**事件广播** —— 长任务进度（导入/识别/增强）往上汇报的方式：壳层在回调里把进度 `emit` 成事件，界面订阅后更新进度条。底层不认识界面，界面也不认识底层。

**客户端校验 / 服务端校验** —— 界面上的校验（如金额格式）目的是**体验**：就近、立刻反馈；后端的校验目的是**防线**：任何入口都绕不过。一句话：**界面校验是给用户的礼貌，后端校验是给数据的保险。**
**唯一约束（数据库兜底）** —— 建表时给某列加的"不许重复"规则，如 `voucher_no UNIQUE`；它是最后一道兜底：就算上层都漏了，数据库也会拒绝写入重复编号。
**纵深防御（多层兜底）** —— 同一件错事在多个层次各拦一次：界面拦格式 → 服务层拦规则（封账/日期）→ 数据库拦底线（唯一约束）。任何一层被绕过，后面还有。

**JSON** —— 一种"写在文本里的数据格式"，形如 `{"id": 12, "amountCents": 3400}`。**界面（JS）和内核（Rust）是两种语言，靠 JSON 互相说话**。
**序列化 / 反序列化** —— 把程序里的对象变成 JSON 文本（发出去）叫序列化；收到 JSON 再变回对象叫反序列化。
**薄命令层（门房）** —— 命令层刻意只做三件事：收参数、转交服务层、把错误翻译成人话。**它自己不写业务规则**——这样规则就只有一处。
**错误码（code / message）** —— 内核回给界面的错误是"一个短代号 + 一句人话"（如 `code: "not_found"` + "凭证 12 不存在"）。界面据代号决定怎么提示，不必看懂 Rust。
**期间锁（封账）** —— 把某个已结账的月份锁住，之后**不允许再改**该月的凭证。服务层在每次修改、删除前都会检查。对应表 `period_locks`。
**修改前快照（留痕）** —— 每次修改凭证前，服务层先把它的**完整原样**存一份（表 `snapshots`，理由记作 `update`），所以改错了能追溯。注意与"备份里的快照"区分：这个在数据库里，那个是备份文件。
**事务边界** —— 一段代码里"必须同成同败"的范围。本项目所有写路径都把它明确画出来（`with_tx(|tx| { … })`），边界内任何一步失败，整段回滚。

**invoke** —— 界面喊内核的方式（"帮我做这件事"）。界面上每个操作最终都变成一次 invoke。
**命令层** —— 内核里"接待"界面的那一层，只负责收参数、转交、回话，不干具体业务。
**服务层** —— 内核里真正干活的层（算账、查重、导出）。
**仓储层** —— 只跟数据库打交道的层（增删查改）。
**越层** —— 命令层绕过服务层直接碰数据库。本项目的门禁会拦下这种写法。
**门禁 / 守卫** —— 一段自动检查，不符合规则就报错，不让代码进仓库。
**契约** —— 两边（比如前端和后端）约好的规则。本项目的"契约测试"会读源码来验证规则没被破坏。
**事务** —— 一组改动"要么全部成功，要么全部不做"。本项目删除重复凭证就是一次事务（留痕与删除同成同败）。
**提交 / 回滚** —— 事务成功落地叫提交；中途出错撤销全部改动叫回滚。
**参数化 SQL** —— 把"值"和"命令"分开传给数据库，防止有人把坏字符串当命令执行（SQL 注入）。
**幂等** —— 同一个操作做一次和做十次，结果一样。本项目的重复判定是幂等的（反复点不会出问题）。
**迁移** —— 版本升级时自动给数据库补新结构。所以你升级不用手工改库。

## 三、钱与口径

**浮点误差（floating-point）** —— 电脑用二进制近似存小数，0.1、0.2 这类数存进去就不精确（`0.1+0.2 = 0.30000000000000004`）。对钱是灾难，所以**存钱绝不用小数**。
**分（整数存钱）** —— 本项目金额一律以"分"存成整数（`33900` = 339.00 元），显示时才打扮成"元"。整数运算永不误差。
**字符串换算** —— 元→分不走乘法（`0.07*100` 可能得 `6.999…`），而是把字符串拆开：整数部分×100、小数部分补齐两位。实现唯一一份在 `src/composables/money.ts`。
**口径唯一化** —— 一个数字的算法全项目只能有一份。本项目两个"唯一实现"：金额换算（`money.ts`）与时间窗口（`dateRange.ts`）；谁都不许自己再写一遍。
**计数 ↔ 列表等价** —— 卡片数字与点进去的清单必须来自同一条口径；凡来自两条查询的，必须有自动用例断言相等。现有五条 `*_matches_list_*` 用例守着。

**分** —— 本项目所有金额都以"分"存成整数（10000 = 100.00 元）。整数不会出现小数误差。
**浮点数误差** —— 用小数存钱会出现 0.1 + 0.2 ≠ 0.3 这类问题，所以我们不用小数存钱。
**口径** —— 同一个数字只能有一种算法。本项目最容易出的一类问题就是"两处算法不一致"。
**计数 ↔ 列表等价** —— 卡片上写"3 张"，点进去必须正好 3 张。我们为每一处这种数字都写了自动用例。
**窗口（时间窗口）** —— 统计的时间范围（含起点和终点）。本项目"本月"就是 1 号到月末。
**环比** —— 和上一个等长的时间段比较（本月 vs 上月）。

## 四、测试与守卫

**断言** —— 一句"我期望是这样"的检查，不成立就报错。
**用例（测试）** —— 一组断言，模拟一个场景跑一遍。本项目目前 **Rust 286 个**（内核 283 + 外壳 3）、**界面 288 个**（49 个测试文件）。
**单元测试 / 集成测试** —— 前者测一小块零件，后者把几块拼起来跑真实流程。
**契约测试（本项目的"守卫"）** —— 不点界面，而是"读源码文本 + 断言规则"，比如"每个页面都必须登记在命令面板里"。
**回归** —— 以前修好的问题又冒出来。用例的作用主要是防回归。
**假绿** —— 测试通过了但其实没测到真东西（比如断言写得太松）。
**覆盖率** —— 代码有多少比例被用例跑到。本项目暂未统计（挂账第 10 项）。
**门禁（本例的"门"）** —— 提交/推送前必须全绿的那几道检查，唯一真源是 `scripts/guards.sh` 与 npm 脚本。日常说"**四门**"＝前端 `typecheck` / `lint` / `test` / `build`；"**三门**"＝Rust `fmt` / `clippy`（`-D warnings`，警告即错误）/ `test`；另有**两道 grep 门禁**：`guards.sh layering` 防命令层直连数据库、`guards.sh platform` 防 Windows 代码回归。改到哪层就跑哪层的门。
**探针验证** —— 故意把代码改坏，看用例是否变红——用来证明"这条用例真的在守东西"。本项目每次新增守卫都这么做。
**CI（持续集成）** —— 你把代码推上去后，GitHub 在别人的机器上自动跑一遍全套检查。

## 五、备份与恢复

**快照 + 附件包** —— 备份两件套：小的是数据库，大的是图片。远端备份时只要图片没变，附件包会跳过不传。
**内容寻址** —— 按图片内容的哈希命名/识别，同一张图永远只有一份。
**加密备份** —— 用密码把备份加密（本项目用 age 算法）。
**恢复演练** —— 不动正在用的库，先把备份在临时目录里展开做一次"体检+对账"，通过了才真恢复。
**原子替换** —— 恢复时不覆盖原文件，而是先写好新文件再"改名顶替"（改名是瞬间完成的，中途断电不会留半个文件）。
**路径归一化** —— 把 Windows 的反斜杠 `\` 统一成 `/`。你遇到的"恢复后缩略图全部无法显示"就是这里出的问题（已修，有用例守着）。

## 六、重复凭证

**内容重复** —— 同一张图（导入时就按哈希拦住，不给进）。
**疑似重复** —— 同日期 + 同金额的凭证（本项目的核心判定口径，宁多报不漏报）。
**编号重复** —— 凭证编号撞车（表单会拦）。
**证据分档** —— 同图 或 同对方+同摘要 = 高置信度；只是同额 = 低置信度。
**处置** —— 对一对疑似重复做结论：「不是重复」（不删任何东西）或「确认重复」（保留一张、删除另一张）。
**留痕** —— 删除凭证前把它的完整内容存进处置记录，事后可追溯。
**归一化（配对）** —— 把一对凭证按 id 从小到大排列后再记录，避免同一对存成两条。
**待处理计数** —— 侧栏徽标上的数字，与核查页清单条数必须一致。

## 七、识别与增强

**OCR** —— 图片转文字。本项目默认**本地识别**（不联网、不上传你的图片）。
**云端 OCR** —— 调用在线服务识别（本项目预留但未启用，需要账号与预算）。
**识别状态** —— pending（排队）/ running（进行中）/ done（完成）/ failed（失败）。
**增强** —— 对图片做去噪、锐化、透视裁剪等处理，让打印更清楚。
**缓存** —— 可随时重建的数据。删掉不心疼，只是下次用要重算。
**置信度** —— 系统对"这个字段识别得准不准"的自评分，三档：高 / 中 / 低。来源越硬档越高（比如发票上的大写金额和小写金额互相印证 = 高）。
**自动填写门控** —— v0.20：只有够可信的字段才自动填进凭证。金额**放开**（只要识别出金额就填——低档"唯一兜底"经 2026-09 基准实测约 98% 正确，多为转账截图，用户 2026-10-09 拍板）；日期和对方"中"档以上才填，"低"档放进识别结果卡等你人工点。摘要永远不自动填。
**大写金额互验** —— 发票上金额印两遍（壹佰壹拾叁元整 ↔ ¥113.00）。两遍对得上 = 双保险（升"高"档）；对不上 = 必有一遍被认错，宁可不填。

## 八、打印与导出

**PDF** —— 打印用的文档格式。本项目生成 PDF 时会**嵌入字体**，所以在别的电脑上打开也不会变字形。
**字体子集化** —— 只嵌入用到的那些字，让 PDF 体积不至于暴涨（中文字体动辄十几 MB）。
**批次** —— 一次导出记一个批次，可在「导出历史」里反查"哪些凭证进过哪次导出"。

## 九、版本、发布与升级

**版本号** —— 形如 `0.19.0`（主.次.修）。本项目要求四处同步：内核配置、界面配置、包描述、锁文件。
**构建** —— 把源码"编译"成可运行的程序。发布用的是优化过的"发布构建"。
**打包 / dmg** —— 把应用封装成可安装的磁盘映像（双击挂载、拖进「应用程序」）。
**dylib** —— macOS 的动态库文件（类似 Windows 的 dll）。本项目要把 OpenCV 的 6 个 dylib 收进安装包。
**@rpath / 自包含** —— 让程序按"包内相对位置"找库，而不是按你机器上的绝对路径，这样换台电脑也能启动。
**ad-hoc 签名** —— 不花钱的"自我签名"，能让系统接受程序运行，但**无法通过公证**（需要 Apple 开发者账号，年费）。
**公证（notarization）** —— Apple 对应用做一次审核并盖章。没有它，别人下载后第一次打开要右键→打开或执行 `xattr` 命令。
**隔离属性（quarantine）** —— 系统给"从网上下载的文件"打的标记，第一次打开会被拦。
**校验和（sha256）** —— 文件的指纹，用来确认下载到的安装包和发布的一模一样。
**自动升级** —— 应用自己检查新版本并下载安装。本项目计划用它（签名不依赖 Apple 账号），下一步就做。
**回滚** —— 出问题时退回上一个版本。

## 十、人与 AI 的分工

**审计** —— 按固定清单把整个项目过一遍并写报告。
**严重度分级** —— P0 数据/安全，P1 发布门，P2 技术债，P3 卫生。
**闭环档位（L1/L2/L3）** —— L1 代码改了；L2 有用例守着（可复现的问题必须到这一档）；L3 真机验过。

## 十一、命令行与工具（第 1 课补充）

**命令行 / 终端** —— 用打字代替点击来操作电脑的地方。命令的通用形状是：**程序名 + 空格 + 去哪里 + 空格 + 干什么**。
**参数** —— 跟在程序名后面的每一段。段与段之间用空格分开。
**引号的作用** —— 把"带空格的整段"当成一个参数。本项目的路径里有 `Application Support`（含空格），所以必须加引号。
**`$HOME`** —— 代表你的主目录（本机是 `/Users/apple`）的变量，终端执行前会替换成真实路径。
**URI 与 `?` 查询参数** —— `?` 是**分隔符**：左边是"打开什么"，右边是"附加要求"，要求写成 `名字=值`，多条用 `&` 连接。例：`file:…/voucher.db?mode=ro`。浏览器地址栏里的 `?q=凭证&page=2` 是同一套约定。**它与"提问"无关**。
**`mode=ro`（只读模式）** —— 打开数据库的"只许看、不许改"方式；`rw` 可读写，`rwc` 可读写且允许新建。我给只读命令时一律用 `ro`。
**点命令** —— `sqlite3` 工具自身的小命令，以 `.` 开头（如 `.tables` 列表、`.schema` 看结构）。**它不是 SQL**：SQL 是问数据，点命令是问工具。
**热更新（HMR）** —— 开发服务器在你改完代码后**不刷新页面**就替换掉那段代码，界面状态保留。好处是改样式立刻可见；坑是"只换函数定义、**已经建好的实例不会跟着换**"——2026-10-16 用户实报的 `withLiveAppearance is not a function` 就是这个坑（store 实例还是旧的，新方法看不见）。
**SQL** —— 问数据库的语言。四个常用动作：`select` 查、`insert` 增、`update` 改、`delete` 删。本项目**只读的事可以用命令行查，写的事一律回界面做**（界面会同时维护编号唯一、留痕、索引等保护）。

## 十二、依赖、锁文件与安全通告

**依赖** —— 别人写好的代码包，直接拿来用。本项目内核用了 `printpdf`（生成 PDF）、`zip`（备份）、`reqwest`（WebDAV）、`rustls`（加密连接）等。
**直接依赖 / 传递依赖** —— 直接 = 你自己在 `Cargo.toml` 里写下名字的；传递 = 依赖的依赖（你没点名，但会被一起装进来）。例：`rustls` 是传递依赖——链路是 `reqwest → hyper-rustls / tokio-rustls → rustls`。
**声明文件（`Cargo.toml`）** —— 回答"**我想要什么**"，用**版本范围**表达。例：`printpdf = "0.7"` 意思是 0.7.x 都可以。
**锁文件（`Cargo.lock`）** —— 回答"**我这次实际用的是哪一个**"：精确到版本 + 来源 + 校验和，**覆盖全部传递依赖**，并且要提交进仓库。它的作用是把"同一份代码 → 永远同一套依赖版本"钉死（可复现构建）；没有它，今天能编、下周换台机器就编出另一套，甚至编不过。前端那份叫 `package-lock.json`。
**版本范围符（`^0.23` / `"0.7"`）** —— 大致是"这个版本及其后续兼容版本"。所以 `cargo update -p rustls` 只会在 `^0.23` 范围内升到最新，不会跳到 0.24。
**校验和（checksum）** —— 锁文件里每个包后面那串哈希，用来确认下载到的包没被替换或损坏。
**`--locked`** —— "就按锁文件来，别顺手改它"。CI 里用 `cargo clippy --locked` / `cargo test --locked`，防止构建过程中悄悄升级依赖；要改就报错。
**`cargo update -p X`** —— 只把锁文件里的 X 升到声明范围内最新。2026-10-16 那次：`rustls 0.23.45 → 0.23.46`，锁文件只动两行（版本 + 校验和）。
**yank（撤回）** —— 发布方把某个版本从 crates.io 撤下。**已锁定它的项目照常能编**，但任何人**新解析**时都选不到它。本项目 `zip 2.4.2` 被撤（属"信号"，不是漏洞；要清掉得连 `rust_xlsxwriter` 一起升 → 挂账 #34）。
**安全通告（RUSTSEC / advisory）** —— Rust 生态的漏洞公告，按**精确版本范围**判定（例：`>=0.23.44, <0.23.46` 受影响）。所以 `Cargo.toml` 里的范围说明不了问题，**只有锁文件知道你到底装的是哪一版**——这就是"5 advisories"的出处。
**`cargo audit`** —— 拿锁文件逐条比对通告库，列出：漏洞 / 无人维护 / 不健全 / 被撤版本。它扫的是锁文件、**不分平台**（所以 macOS 根本不编译的 `rustls` 也会被报出来）。
**Security audit（CI 上那条红叉）** —— CI 的 `deps-audit` job 里 `rustsec/audit-check` 跑完 `cargo audit` 后，**自己再发一个检查**，名字就叫 Security audit。对应的 job 是 `continue-on-error`，属于**非阻塞信号**：所以"CI 总体 success、这条 check 红"是正常组合，不是构建失败。
**可达性** —— 判断一条通告要不要紧的第一问：**那个出问题的函数，我们代码里真的会调到吗？** 例：`lopdf` 的栈溢出只在**解析**构造的 PDF 时触发，而本项目只**写**不读 PDF → 不可达 → 挂账 #33 决定不处理。
**`.gitattributes` 的 `*.lock binary`** —— 把锁文件按二进制对待：默认 `git diff` / `git show` **看不见内容变化**（要加 `--text`），同时关掉锁文件的自动合并。本项目 2026-10-16 决定暂不改（理由与复查触发条件见 `docs/开发日志.md` 第十六笔）。
