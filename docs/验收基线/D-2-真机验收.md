**核心 DDL**（节选自 `SCHEMA_V4`）：

```sql
-- v4：增强版被实际使用的次数（OCR 读取 / 导出 / 查看器打开都算 hit）
CREATE TABLE IF NOT EXISTS enhance_hits (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    attachment_id INTEGER NOT NULL REFERENCES attachments(id) ON DELETE CASCADE,
    source        TEXT    NOT NULL
                  CHECK (source IN ('ocr','export','viewer')),
    hit_at        TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_enhance_hits_attachment ON enhance_hits(attachment_id);
CREATE INDEX IF NOT EXISTS idx_enhance_hits_hit_at     ON enhance_hits(hit_at);
```

### 7.3 关键观察

1. **命中率刷新链路完整**：`d2_seed_hits` 写入 23 条命中 → 切到设置页 → 摘要卡显示「累计 23 / 30 天 23 / 活跃 67%」（前 4 张有命中，6 张总数）。刷新按钮 ↻ 立即拉新数据，无需重启。
2. **单条释放二次确认态**：第一次点列表中某行「释放」按钮 → 变成「再点确认」+ 红色脉冲动画（`@keyframes d2-pulse`），5 秒内有效；超时自动撤销回「释放」态。这是「降低误删率」的关键 UX 改造。
3. **多策略互斥切换**：选「全部」时数字输入隐藏（显示「30」「10」灰色占位）；选「早于 N 天」或「大于 N MB」时才出现数字输入框，`v-if` 控制。
4. **mtime 判定 vs created_at**：`d2_age_some` 把 id=1, id=2 增强版 mtime 改到 60 天前；「早于 30 天」策略应只命中这两张。`d2_clear_v2_larger_than_mb_respects_threshold` 测试用 mtime 路径已覆盖。
5. **大小数字与真实一致**：摘要卡 `(totalSize/1048576).toFixed(1)` 显示 MB；列表行 `(enhancedSize/1024).toFixed(0)` 显示 KB。两者数据来源相同（`std::fs::metadata.len()`），但显示精度不同。
6. **全清后归零**：选「全部」策略 + confirm 确认 → 6 张全清，摘要变 `0 个增强版 / 0 MB`，最近列表回到空态（"尚无增强记录"）。再次 OCR 同一张图时，OCR 走 fallback 原图路径（不写 hit），且增强版文件按 hash 自动重建。
7. **暗色主题无回归**：增强缓存面板用 `var(--surface-2) / --stroke / --accent` 全部 token 化；深色 / 浅色下均无对比度问题。
8. **无跨页状态泄漏**：D-1 编辑页的 `useEnhanced: Record<number, boolean>` 与 D-2 设置页的 `pendingDeleteOne: number | null` 互不影响，组件卸载时 ref 自动回收。

## 9. 已知限制 / 后续可改进

- **导出命中占位**：v0.6.5 暂未接通 `Export` / `Viewer` 来源的真正写入。Rust → WebView2 调度的 PDF 生成器 / 图片查看器都是 v0.6.6 候选；schema 留好位，命中函数预留 `HitSource::Export / Viewer` 两个变体。
- **mtime 判定 vs created_at**：用文件 mtime（写盘时间）比 `attachments.created_at`（导入时间）更准——增强版可能因热替换 / 备份恢复而被改写。代价：用户手动复制粘贴会"老于 N 天"误命中，可接受。
- **单条释放的二次确认超时**硬编码 5 秒**：**未来如需可配置，可放设置页「常规」Tab 的「缓存」分组；当前 5 秒已是 Win11 通用 UX（Copy 撤销 toast 也是 5 秒）。
- **`larger_than_mb` 阈值上限 500 MB**：单张增强版 JPEG 一般 100-300 KB，500 MB 已远超常规；如需调高改 `SettingsPage.vue:556` 的 `max="500"`。
- **0 除零保护分散**：`hitCount30d` / `hitCount` 不会除零；唯一一处 `total > 0 ? ... : 0%` 在「活跃占比」分行，避免 N/A 字符串。
- **确认弹窗**用原生 `confirm()`**：**未走 ConfirmDialog 组件（避免重复造轮子；释放是不可逆但低风险操作，原生 confirm 已够用）。如需可加 `ConfirmDialog` 走一致 UI。
