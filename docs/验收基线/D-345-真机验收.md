## D-3 翻页预取缓存

### 1.1 现状与目标

- **现状**（D-1 已落位）：列表页 20/页翻页是显式点击 › 按钮；点击时调 `api.listVouchers`，UI 进 loading 态，等 100-300ms 数据回来才替换 items/thumbs。
- **目标**：hover › 200ms 静默预取下一页 → 点击 › 命中缓存瞬时切换。
- **不做什么**：不改滚动容器（当前是普通 div，20 行直接铺底；改滚动会动结构）；不预取 2 页之后（边际收益低 + 内存膨胀）。

## D-5 导出命中接通

### 3.1 现状与目标

- **现状**（v0.6.5 D-2 落位）：`enhance_hits` 表已就位、HitSource 枚举已含 `Export`、OCR 路径已写 Ocr 命中。但导出 PDF 路径没接通——`HitSource::Export` 永远 0。
- **目标**：`export_vouchers_pdf` / `export_vouchers_daily` 在 PDF 生成 + 落批次记录后，每张有 `enhanced_path` 的附件写一条 `Export` 命中。
- **口径演进**：D-6 落位后收紧为「增强版**实际进了 PDF** 的附件才计命中」（截图增强版仅 OCR 用、不进 PDF，故不再计 Export），避免命中率虚高。

/// 落批次记录 + 明细 + 状态流转（非归档 → 已导出，先落快照）
/// D-5：同步记录每张被导出图附件的 `enhance_hits` 命中（source='export'）
fn record_batch(
    ctx: &CoreContext,
    items: &[(Voucher, Vec<Attachment>)],
    batch_no: String,
    pdf_path: String,
) -> Result<ExportBatch> {
    let count = items.len() as i64;
    let batch = ctx.db.with_tx(|tx| {
        // ... 落批次 + 状态流转 ...
        Ok(batch)
    })?;

    // D-5 增强版命中埋点（D-6 收紧口径）：只有增强版实际进了 PDF 的附件
    // （扫描件 + enhanced_path 存在 + 文件在盘）才算一次 Export 命中，
    // 与 pdf_image_abs 的取图规则完全一致，避免命中率虚高。
    for (_v, atts) in items {
        for a in atts.iter().filter(|a| a.is_image() && uses_enhanced_in_pdf(ctx, a)) {
            if let Err(e) = ctx.db.with_conn(|conn| {
                enhance_hit_repo::record(conn, a.id, enhance_hit_repo::HitSource::Export)
            }) {
                log::warn!("记录 enhance_hits(Export) 失败（不影响导出）: {e}");
            }
        }
    }

    Ok(batch)
}
```

## D-6 PDF 附录图片优先增强版

### 5.1 现状与目标

- **现状**（D-5 遗留）：`PdfImage.path` 硬编码 `attachment_repo.file_path`——PDF 附录一律印原图，5 步矫正后的增强版没进 PDF；且命中埋点把所有带 `enhanced_path` 的附件都记 Export，口径虚高。

/// 截图/未识别回退原图（截图增强版仅用于 OCR，不进 PDF）。
pub fn pdf_image_abs(ctx: &CoreContext, a: &Attachment) -> std::path::PathBuf {
    if a.enhanced_source == EnhanceSource::Scan {
        if let Some(ep) = &a.enhanced_path {
            let abs = ctx.paths.attachment_abs(ep);
            if abs.exists() {
                return abs;
            }
            log::warn!("增强版文件缺失，PDF 回退原图: {}", abs.display());
        }
    }
    ctx.paths.attachment_abs(&a.file_path)
}
```

### 9.8 关键观察

1. **D-3 内存安全**：每个 listKey 最多 2 页缓存（page 当前 + page+1），单 key 约 60-80 个 Voucher 对象 / 80KB 内存；切换筛选自动清空。
2. **D-3 无 loading 闪烁**：`load()` 命中缓存分支不设 `loading.value = true`；只有 `await api.listVouchers` 才进 loading 态。
3. **D-4 性能**：双层 img 一次性 `convertFileSrc` 拼 URL → WebView 一次性拉两份（用 HTTP 缓存），拖滑块只改 `clip-path` 内联样式，**无网络往返、无重解码**。
4. **D-4 对比层不会越界**：原图层用 `object-fit: contain` 保比例；att-img `overflow: hidden` 兜底。
5. **D-5/D-6 口径一致**：命中过滤与取图共用 `uses_enhanced_in_pdf`——「导出」tag 数 = 实际印增强版的次数，不虚高；截图件导出既印原图也不计命中。
6. **D-7 三来源闭环**：OCR（D-2）/ 导出（D-5+D-6）/ 查看（D-7）全部接通；无增强版的附件查看不计命中。
7. **D-5 错误隔离**：写命中失败时 `log::warn!` 仅记录到日志，PDF 批次 + 状态流转已落库，**不撤、不重试**——避免导出回滚。
8. **D-9 零额外请求**：附录预览复用分页已拉取的 `VoucherThumb`，不重复解码；`loading="lazy"` 按需加载。

## 已知限制 / 后续可改进

- **D-3 不预取 2 页之后**：单 key 最多缓存 2 页。如果用户从 page=1 跳到 page=5（通过直接编辑 URL？当前无此入口），仍会发请求。可接受。
- **D-4 双层图都全量加载**：底层原图和上层增强版都是原始分辨率（~1-2 MB / 张）；OCR 校对场景下缩略图区显示足够，无内存问题。若要压缩，可补 `object-fit: cover` 调比例或走 blob。
- **D-4 无键盘快捷键**：拖滑块只能用鼠标；Tab + 方向键也能操作但无视觉提示。v0.6.5 范围内不做。
- **D-6 截图件 PDF 恒印原图**：设计如此（截图增强版仅 OCR 用，PDF 保留彩色原貌更可读）。若未来要「截图也印增强版」，只需在 `pdf_image_abs` 放开 Screenshot 分支，但需同步评估可读性。
- **D-7 每次打开都计一次**：重复查看同一附件会累计多条 Viewer 命中（反映真实使用频次）。若要「每附件至多一条」，需去重表或 UPSERT，v0.6.5 不做。
- **D-9 预览只显示前 8 张**：网格 `slice(0, 8)` 防止长列表把预览区撑爆；完整附录以导出的 PDF 为准（有文字提示）。
