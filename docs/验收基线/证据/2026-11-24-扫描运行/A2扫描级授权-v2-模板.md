## 1. 为什么要 v2

`A2扫描级授权-01.json` 已在 2026-11-24 01:10Z 消费一次（`exit 0`，不可重放）。Q2 五条流程约束在当天第二轮才落码，**已消费的原件不含 `approved_file_id`**，按现行规则 `--check` 会报 `P2_E_GRANT`、执行会报 `P2_E_SCOPE_PENDING`；原件不追改（`2026-11-24-扫描运行/实现证据.md:80`）。因此下一次扫描签批必须换用本模板。

## 3. 字段契约（签批人逐格填，缺一格即不可签）

| 字段 | 必填 | 语义 | 代码校验点 | 失败码 / 现象 | 填写人 |
|---|---|---|---|---|---|
| `grant_id` | 是 | 授权单编号，**一次性**；重复即 `P2_E_ALREADY_USED` | `wps_p2.rs:1548-1551`、`consume` `wps_p2.rs:1720` | `P2_E_NOT_APPROVED` / `P2_E_ALREADY_USED` | 开发 |
| `approved_by` | 是 | 签批人（本人签署）。**不得**再用它当账号主体 | `main.rs:496` | 缺键 → `P2_E_GRANT`、exit 2 | 用户 |
| `endpoint` | 是 | 真实端点域名；CLI 默认只许回环，真实端点须加 `--allow-real-endpoint` | `main.rs:502-507` | `P2_E_GRANT` | 安全/运维 |
| `file_id` | 是 | 请求目标：唯一非生产副本 | `main.rs:508` | `P2_E_GRANT` | 用户 |
| `approved_file_id` | **是（v2 新增）** | 签批目标；必须与 `file_id` 逐字一致 | `main.rs:508-509`、`wps_p2.rs:1552` | 缺键 `P2_E_GRANT`；不一致 `P2_E_TARGET` | 用户 |
| `approved_subject` | **是（v2 升格）** | 签批授权主体（账号/租户）；**自述**，非服务端核对 | `main.rs:512`、`wps_p2.rs:1615` | 缺失 `P2_E_SCOPE_PENDING`；不一致 `P2_E_SCOPE` | 用户 |
| `sheets[]` | 是 | 每表 `sheet_id` + `fields`（逐列批准）+ `pages`（锁死页数） | `main.rs:513-548` | 缺项/空字段/空 pages → `P2_E_GRANT` | 开发 |
| `page_size` | 是 | 单页条数（v1 用 50） | `main.rs:549`、`wps_p2.rs:1560` | `P2_E_GRANT` / `P2_E_PAGE_SIZE` | 开发 |
| `window_start` / `window_end` | 是 | UTC；**窗口 ≤15 分钟** | `main.rs:550-551`、`wps_p2.rs:1573-1588` | `P2_E_GRANT` / `P2_E_WINDOW` | 用户 |
| `max_reads` | 否（默认 `2×Σpages`） | 读取硬上限，`≥2×Σpages` 且 `≤74` | `wps_p2.rs:1590-1600` | `P2_E_EXEC_LIMIT` | 开发 |
| `max_total_requests` | 否（默认 `max_reads+6`） | 整场上限，`≤80` 且为会话留 `≥3` 次 | `wps_p2.rs:1601-1608` | `P2_E_EXEC_LIMIT` | 开发 |
| `terminate_allowed` | 否（默认 `true`） | 允许 `DELETE` 收尾（**仅 1 次**） | `main.rs:553-556` | — | 安全/运维 |
| `build_commit` / `binary_sha256` | 流程必填 | 签前锁定构建与二进制 | **代码不校验**（`--check` 不读） | 但签前检查表要求有值 | 开发 |
| `expected_rows` / `expected_pages_per_pass` / `required_reads` | 流程必填 | 签前 24h 内实测的行数/页数/必达读取 | 代码不校验（`required_reads` 由 `pages` 现算） | 实测值与签发值不符即不得签 | 开发 |
| `signature` | 是（人工） | 签批人签署 | 代码不校验 | 空即未签 | 用户 |

> **签名与 `approved_by` 的关系**：`approved_by` 非空即可通过 `validate`（`wps_p2.rs:1556`），**代码不会验证签名真伪**。因此「已签」只能由人工签署栏与留痕证明，不能由 `--check` 通过反推。
