# C5 本地辅助证据：本地索引全字段指纹

> 结论先说：**这份证据不能关闭 C5，也不解除写入阻断。** 它只回答「两次扫描之间，本地索引是否逐字段一致」；因为 SkillHub 的 `dbsheet.list_records` 不提供快照 token，「源端与本地一致」仍然无法在本地证明。

## 1. 它解决什么

C5 的必验项是「无法证明本轮关键字段一致 → 一律阻断写入」。真实副本的 C5 需要在授权窗口内从拟放行写入入口触发，并归档三项（扫描诊断、入口阻断结果、传输层 0 次 create）。

在拿到真实副本授权之前，能先做的是把「扫描期间数据在变」这一类风险做成可复现检查：

- 逐表按 `record_id` 升序，把 `(record_id, 规范化 fields_json)` 连成行取 `sha256`；
- `fields_json` 先解析再重新序列化，消除键序/空白造成的假差异；
- 整库指纹 = 对 `sheet_id|records|digest` 行再取 `sha256`；
- 两次指纹不同 → 报告变化的表号与计数（**不回显任何字段值**）。

## 2. 怎么跑

```bash
# 只读、零发网：打印当前本地索引的指纹
cargo run -q -p voucher-cli --offline -- c5-fingerprint --json --data-dir <隔离目录>
```

判读：两次扫描后 `combined` 相同且 `sheets[].digest` 相同 → 本地索引稳定；任何差异都会落在具体表号上。

## 3. 实跑证据（2026-11-23，Mock 全量拉取 + 一次人工漂移）

命令：`cargo test -p voucher-core --lib --offline services::wps_c5 -- --nocapture`

```
C5_FP records=3 combined=1666f03db874 sheets=3 stable=true
C5_FP_DRIFT changed_sheets=[1] reason=["表 1 字段指纹不同：1 条/4a90d20a96a4 vs 1 条/976a54cfc531"]
```

- 第 1 行：Mock 全量拉取后连续两次指纹完全一致（`stable=true`）；
- 第 2 行：对表 1 的一条记录改字段值后，指纹变化且**只指向表 1**（反向对照成立）。

用例（6 例，`services::wps_c5`）：`identical_index_yields_identical_fingerprint`、`field_change_is_detected_per_sheet`、`key_order_and_whitespace_do_not_create_false_diff`、`added_and_removed_sheets_are_reported`、`invalid_fields_json_is_an_error_not_a_silent_skip`、`mock_pull_is_stable_and_drift_is_detected`。

## 4. 不能得出什么

| 命题 | 能否由本证据得出 |
|---|---|
| 两次扫描之间本地索引逐字段未变 | ✅ |
| 扫描期间源端未被修改 | ❌（两次都读到同一错误值也会「稳定」） |
| WPS 源端字段与本地一致 | ❌（无快照 token） |
| 可以解除 C5 写入阻断 | ❌ |

## 5. 与真实 C5 的关系

- 本证据是**前置辅助**：在真实副本上，若两次指纹不一致，直接停止并记录，不必进入写入预检；
- 真实 C5 仍需按 `签审决策表.md` §4 的三项归档执行（扫描诊断、入口阻断结果、传输层 0 次 create），入口从拟放行写入路径触发；
- 状态：C5 写入阻断**维持**，C1–C6 全部未执行。
