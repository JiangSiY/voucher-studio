## 2. 请求计数（修复前后）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 会话过期 → 超时 → 5xx → 成功（脚本 4 条） | 实际调用 4 次，`attempts_used=3`，第 4 条“成功”被取用 | 实际调用 3 次，预算耗尽即停止（返回 `P2_E_SERVER`），第 4 条成功未被消费 |
| 会话过期 → 成功（预算内重建） | `attempts_used=2`、调用 2 次 | `attempts_used=2`、调用 2 次、初始化 2 次（不变） |
| 最后一次读取额度用完后再次会话过期（第四轮） | 未覆盖 | 读取 3 次后直接停止（`P2_E_SESSION`），初始化仍为 1 次，**不再重建会话** |
| 全部 5xx | 3 次调用后停止 | 3 次调用后停止（不变） |

根因：旧实现先自增再调用，会话过期分支又 `attempts -= 1` 归还额度，导致「已发出 4 次却只记 3 次」，且归还后能再发第 4 次，突破「单次逻辑读取最多 3 次请求」口径。修复后预算在调用前扣减，重建不归还。

| `crates/voucher-core/src/services/wps_p2.rs` 测试模块（2026-11-23 第六轮：跨进程） | 36 例（+4：`p2_child_worker` 子进程入口 + 重启、并发、登记后中断三个跨进程用例）；子进程复用本测试二进制（`current_exe --exact … p2_child_worker`），同一状态库文件、同一授权 ID、同一本机 HTTPS 服务 |

### 3.1 响应越界：同一 P2 入口的验收证据（2026-11-22 第三轮）

入口与传输：`HttpsP2Transport` → 本机 rustls HTTPS 服务（`TLS_SRV_CERT`，`p2-local.test` 固定解析到 `127.0.0.1`）。服务端按 MCP `tools/call` 形状返回 `result.content[0].text` 内含 JSON 负载，其中一条记录带未授权字段 `SECRET`。

| 验收点 | 证据 | 结论 |
|---|---|---|
| 整页拒绝 | `read()` 返回 `Err(P2_E_SCOPE)`；`validate_records` 命中未授权键即整体返回，不返回部分记录 | 整页拒绝，非静默丢弃 |
| 零业务记录落库 | `P2ReadOnlyEntry` 不持有任何数据库/存储句柄（类型上没有 store 参数），越界分支只返回错误；用例断言 `Err` 且无 `P2ReadOutcome` | 本层零落库；持久化属调用方，未接入 |
| 执行结果醒目提示（第五轮脱敏） | `err.to_string()` = `P2_E_SCOPE: 响应包含未授权字段，整页已拒绝（表 3）`；断言不含远端字段名 `SECRET`、字段值与合成 token | 固定提示 + 错误码 + 表号；**界面层未接入 P2**（桌面面板只覆盖 W2） |
| 脱敏审计 | `with_audit_sink` 捕获一行：`p2 action=dbsheet.list_records host=p2-local.test file=dbsh…01 sheet=3 outcome=P2_E_SCOPE attempts=1`；断言不含完整 `file_id`、`SECRET`/字段值、token | 一行、掩码、无值 |
| 本轮无后续分页/重试 | 服务端请求计数 = 3（初始化 + 通知 + 1 读取），之后无请求 | 停止本次 P2，不再分页/重试，也不发终止 |
| 越界后不可再次启动（第四轮） | 同一入口再读一次 → `P2_E_SINGLE_USE`，服务端计数仍为 3 | 授权占用后不可重启 |
| 越界后跨入口不可重启（第五轮） | 同库新入口再读 → `P2_E_ALREADY_USED`，服务端计数不变 | 与 §3.3 的持久登记一致 |
| 合法响应正对照 | `p2_https_legal_read_runs_full_chain_with_trusted_ca`：同一入口、同一服务端（不注入 `SECRET`）返回 1 条授权字段记录，`attempts_used=1`、请求 4 次（初始化 + 通知 + 读取 + 终止） | 同一入口正反对照成立 |

### 3.2 单次执行入口：动作计数与回归（2026-11-23 第四轮）

同一入口（`P2ReadOnlyEntry` + `HttpsP2Transport` + 本机 rustls 服务），服务端按已完成的请求逐条计数。

**绑定与预算**

| 约束 | 实现 | 违反时 |
|---|---|---|
| 单次授权（不可重启） | 进程内 `claimed`（key = 签批人 + `file_id` + 窗口起点）+ 跨进程的隔离 SQLite 状态库（§3.3）；预检通过即占用 | `P2_E_SINGLE_USE`（同入口）/ `P2_E_ALREADY_USED`（跨入口/重启）/ `P2_E_STATE`（状态库不可用），均零请求 |
| 只读首屏 | `request.offset` 必须为 0 | `P2_E_OFFSET`（零请求） |
| 批准的分页大小 | `request.page_size` 必须等于 `grant.page_size` | `P2_E_PAGE_SIZE`（零请求） |
| 一张表 | `sheets.len() > 1` 即拒 | `P2_E_SCOPE`（零请求） |
| 整场请求上限 | 每次发网前 `reserve` 检查 `total < max_total_requests` | `P2_E_EXEC_LIMIT` |
| 窗口 | 每次发网前取窗口剩余时间；退避时若剩余 ≤ backoff 即停 | `P2_E_WINDOW` |
| 请求超时 | `deadline` = 窗口剩余时间，传输层用 `deadline.min(timeout)` | 超时 → `P2_E_TIMEOUT` |

动作分配（`P2ActionCounts`，无泛化探测余量）：初始化 ≤2（初次 + 至多一次重建）、通知 ≤2（每次初始化后一次）、读取 ≤3（含重建后重发与重试）、终止 ≤1（仅在读取成功后按授权开关执行；失败只做本地关闭，不再发网）。

**正常首屏（`p2_https_legal_read_runs_full_chain_with_trusted_ca`）**：`P2ActionCounts { initialize: 1, read: 1, notify: 1, terminate: 1, total: 4 }`，服务端计数 4，记录 1 条，`attempts_used=1`。

**本轮新增回归（均用服务端计数）**

| 场景 | 结果码 | 服务端请求 | 用例 |
|---|---|---|---|
| `offset=50`（非首屏） | `P2_E_OFFSET` | 0 | `p2_https_non_first_page_and_unapproved_page_size_make_zero_requests` |
| `page_size=20`（与签批 50 不符） | `P2_E_PAGE_SIZE` | 0 | 同上 |
| 退避期间窗口到期 | `P2_E_WINDOW` | 3（初始化 + 通知 + 首次读取） | `p2_https_window_expiry_during_backoff_stops_without_next_request` |
| 整场预算耗尽（上限 3） | `P2_E_EXEC_LIMIT` | 3 | `p2_https_total_request_cap_stops_before_next_request` |
| 完成后重复启动 | `P2_E_SINGLE_USE` | 4（不增加） | `p2_https_completed_authorization_cannot_restart` |
| 越界停止后再启动 | `P2_E_SCOPE` → `P2_E_SINGLE_USE` | 3（不增加） | `p2_https_out_of_scope_stops_and_authorization_cannot_restart` |
| 最后一次额度用完遇会话过期 | `P2_E_SESSION` | 5（初始化 1 + 通知 1 + 读取 3，**无重建**） | `p2_https_last_read_attempt_session_expiry_skips_reinitialization` |

验证层级：全部为本机 HTTPS 服务 + 合成凭据 + 合成授权；**未**连接真实 WPS，**未**使用真实 token，**未**访问真实副本。桌面 UI 本轮后置（P2 尚无界面读数入口）。

覆盖层说明：证据止于 **P2 数据层**（错误对象 + 审计行 + 请求计数）。桌面界面目前没有 P2 读数入口，因此「醒目提示」只验证到 `P2Error` 的展示文案，未验证 UI 渲染。

### 3.3 跨重启消费登记与终止状态（2026-11-23 第五轮）

同一入口 + 隔离 SQLite 状态库 + 本机 HTTPS 服务；状态库只存 `grant_id`、登记时间、掩码副本号、窗口终点。

| 场景 | 机制 | 结果 | 用例 |
|---|---|---|---|
| 合法执行 | 发网前 `INSERT` 登记成功 | 正常 4 次请求，`termination=Completed` | `p2_https_legal_read_runs_full_chain_with_trusted_ca` |
| 重建入口（模拟重启） | 新入口、新连接、同一状态库、同一授权 | `P2_E_ALREADY_USED`，服务端计数不增加 | `p2_consumed_grant_cannot_restart_after_entry_rebuild` |
| 两进程并发 | 两线程各自打开同一 SQLite 文件，`PRIMARY KEY` 保证原子性 | 一个成功、一个 `P2_E_ALREADY_USED` | `p2_concurrent_entries_only_one_claims_sqlite_state` |
| 登记后、发网前中断 | 登记已提交，初始化即失败 | 重启后 `P2_E_ALREADY_USED`；全程 0 次 `list_records` | `p2_claim_survives_crash_before_send` |
| 状态库不可用 | `open` 失败 → `P2_E_STATE`；登记失败 → `P2_E_STATE` | 零请求 | `p2_unusable_state_store_stops_before_any_request` |
| 窗口 >15 分钟 | `preflight` 强制 `P2_MAX_WINDOW` | `P2_E_WINDOW`，零请求 | `p2_window_longer_than_limit_and_total_over_cap_are_rejected` |
| 整场 >8 次 | `preflight` 强制 `P2_MAX_TOTAL_REQUESTS` | `P2_E_EXEC_LIMIT`，零请求 | 同上 |
| `DELETE` 失败 | 读取成功后终止失败 | `termination=Unconfirmed`，消息「远端终止未确认，本地已关闭」，请求仍为 4 次（不追加） | `p2_https_terminate_failure_reports_unconfirmed_without_extra_requests` |
| 预算耗尽未发终止 | 终止前 `reserve` 失败 | `termination=Skipped(P2_E_EXEC_LIMIT…)`，请求 3 次 | `p2_https_terminate_skipped_when_budget_exhausted` |

验证层级同 §3.2：本机 HTTPS + 合成凭据 + 合成授权；未连接真实 WPS、未使用真实 token、未访问真实副本。状态库路径由调用方（签审执行人）在隔离目录给出，本轮用 `tempfile` 临时目录。


### 3.4 跨进程验收：单次授权在独立进程中同样只能消费一次（2026-11-23 第六轮实跑）

方式：父进程起本机 HTTPS 服务，子进程用 `std::env::current_exe()` 重入本测试二进制（`--exact services::wps_p2::tests::p2_child_worker`），经环境变量拿到隔离状态库路径、授权 ID、服务端口与同步目录；每个场景独立 `tempfile` 目录与独立 `grant_id`。

复跑命令与证据日志：

```bash
cargo test -p voucher-core --lib --offline services::wps_p2::tests::p2_cross_process \
  -- --test-threads=1 --nocapture
# 3 passed；输出 CP1/CP2/CP3 行，日志 /tmp/vs-p2r6-cp.log
```

| 场景 | 进程与同步 | 退出结果 | 错误码 | 服务端请求增量 |
|---|---|---|---|---|
| 正常退出后重启 | A(pid 99595) 合法读取后退出；B(pid 99597) 用同一授权、同一状态库重启 | A `CHILD_OK`（`termination=远端终止已确认`，actions 1/1/1/1，total 4）；B `CHILD_ERR` | A 无；B `P2_E_ALREADY_USED` | A 后 `4`；B 后仍 `4`（新增 `0`） |
| 两进程并发 | A(pid 99582)、B(pid 99583) 各自写 `ready-*` 后等待 `go`，父进程看到两个就绪文件后放行 | 恰好一个 `CHILD_OK`、一个 `CHILD_ERR`（`ok=1 used=1`） | 失败方 `P2_E_ALREADY_USED` | 服务端总计 `4`（只发生一轮读取） |
| 登记提交后、首次发网前中断 | 子进程(pid 99592) 用 `PausingConsumption`：`INSERT` 提交后写 `consumed` 标记并阻塞；父进程确认标记与服务端 `0` 请求后 `kill` | 父进程 `after_kill=0`；重启子进程(pid 99594) `CHILD_ERR` | 重启方 `P2_E_ALREADY_USED` | 全程 `0`，重启后仍 `0` |

对照与说明：

- 中断时点由 `consumed` 标记 + 父进程读取服务端计数固定，不依赖 `sleep` 猜测；`PausingConsumption` 只存在于测试模块。
- 三个场景均未新建生产代码路径：子进程调用的就是 `P2ReadOnlyEntry::read` 与 `SqliteP2State`；测试辅助仅为「子进程入口 + 同步点」。
- 服务端计数为本机 rustls 测试服务的已完成请求数（初始化 + `notifications/initialized` + 读取 + `DELETE` 各计 1）。
- 验证层级同 §3.2：合成凭据、合成授权（`A2-2026-11-23-CP-01/02/03`）、本机 HTTPS、隔离目录；无真实 WPS、无真实 token、无真实副本、无生产库。

## 5. TLS、重定向、会话与重试

- `P2TlsPolicy` 默认全严格；`.no_proxy()` 避免环境代理改写目标（本机实测曾被系统代理拦截，已固定关闭）。
- `classify_http_status`：3xx → `P2_E_REDIRECT`（不跟随）；401/403 → `P2_E_AUTH`；404 → `P2_E_SESSION`；429 → `P2_E_RATE`；5xx → `P2_E_SERVER`。
- `map_transport_error`：超时 → `P2_E_TIMEOUT`；错误链含 hostname/host name/dnsname → `P2_E_HOST`；含 certificate/tls/ssl → `P2_E_TLS`；其余 → `P2_E_PROTOCOL`。只归类，不回显原始文本。
- 读取预算见 §2；会话过期最多重建一次，重建消耗已发出的那一次预算；最后一次额度用完时不再重建。
- 初始化成功后发一次 `notifications/initialized`（计数 1）；读取成功后按 `terminate_allowed` 发 `DELETE`（计数 ≤1），终止失败只做本地关闭。
- 单次请求超时 = `min(窗口剩余时间, 传输层 timeout)`。
- 审计行：`p2 action=dbsheet.list_records host=… file=dbsh…01 sheet=3 outcome=… attempts=…`，不含完整 `file_id` 与 token。

### 6.2 单次读取预算 vs 整场取证上限

- **单次逻辑读取**：最多真实发出 **3** 次 `list_records`（首次、会话重建后的重发、超时/5xx 重试均计入）；初始化独立计数、初次后最多重建一次且不重置预算（`P2_MAX_READ_ATTEMPTS`，见 §2）。
- **整场取证**：由授权单另行限定（6.1 的 HTTP ≤8 次按动作分配、单页 50、单窗口 15 分钟、不追分页）。单次预算不因整场上限放宽，整场上限也不因单次预算未用满而追加。
- **动作预算**（第四轮实现）：初始化 ≤2、通知 ≤2、读取 ≤3、终止 ≤1；每次发网前同时检查窗口剩余与整场上限，任一不满足即停，**不做探测性请求**。

## 8. 真实 429 / 400006 的处理条款（拟批）

1. 若 A2 窗口内真实 429 未自然出现：P2 记「未观察，待专项验收」，**禁止刷请求触发**；不因此判定 P2 不通过，但必须写明未覆盖。
2. 400006（授权失效）如需主动演练：由签审人另批隔离账号与窗口；演练前明确「缺证是否阻塞 S0」；未另批则记「真实重授权未演练」。
3. 两类错误在代码侧均已映射（`P2_E_RATE` / `P2_E_AUTH`）且属于「停止本次读取」而非重试项之外的动作；真实响应文本仍不回显。

## 9. 待拍板（简短）

1. 是否先按 §6 补齐 A2 参数（副本/表字段/主体/窗口/端点），再排首次获批联调。
2. 真实端点报文差异由谁在首次联调中确认与回归（开发执行、安全运维核验）。
3. 真实 429/400006 未自然出现时，是否接受 §8 的「保留待验 + 专项演练另批」。
4. 响应侧字段越界处置（整页拒绝 + 审计 + 停止 P2）是否足够，是否另需告警。
5. 单次执行入口的「授权不可重启」已改为**隔离 SQLite 状态库持久登记**（跨重启/并发有效）；仍需拍板的是：状态库路径与保留周期由谁指定、异常时是否需要人工解锁流程。
6. `fields` 投影无法证实时的「合成专用表」备选是否可接受（见 §6.4）。
