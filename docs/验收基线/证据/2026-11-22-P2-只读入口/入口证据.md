## 2. 请求计数（修复前后）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 会话过期 → 超时 → 5xx → 成功（脚本 4 条） | 实际调用 4 次，`attempts_used=3`，第 4 条“成功”被取用 | 实际调用 3 次，预算耗尽即停止（返回 `P2_E_SERVER`），第 4 条成功未被消费 |
| 会话过期 → 成功（预算内重建） | `attempts_used=2`、调用 2 次 | `attempts_used=2`、调用 2 次、初始化 2 次（不变） |
| 全部 5xx | 3 次调用后停止 | 3 次调用后停止（不变） |

根因：旧实现先自增再调用，会话过期分支又 `attempts -= 1` 归还额度，导致「已发出 4 次却只记 3 次」，且归还后能再发第 4 次，突破「单次逻辑读取最多 3 次请求」口径。修复后预算在调用前扣减，重建不归还。

## 3. 零请求对照表

「请求」= 真实 HTTP 请求数（本机 HTTPS 服务按已完成的请求计数；TLS 握手失败计 0）。

| 场景 | 结果码 | 请求数 | 用例 |
|---|---|---|---|
| 入口默认关闭 | `P2_E_CLOSED` | 0 | `p2_default_gate_is_closed_and_issues_zero_requests` |
| 授权缺签批人 | `P2_E_NOT_APPROVED` | 0 | `p2_rejects_unapproved_or_write_actions` |
| 目标 `file_id` 与签批不符 | `P2_E_TARGET` | 0（真实传输同验） | `p2_denies_unapproved_target_before_any_request`、`p2_https_wrong_target_and_write_action_issue_zero_connections` |
| 请求表号不在签批范围 | `P2_E_SCOPE` | 0 | `p2_denies_sheet_outside_grant_and_response_field_outside_grant` |
| 窗口外 | `P2_E_WINDOW` | 0 | `p2_denies_expired_window_and_unapproved_or_mismatched_subject` |
| 凭据主体不符 / 无法核对 | `P2_E_SCOPE` / `P2_E_SCOPE_PENDING` | 0 | 同上 |
| 写动作 / 未知动作 | `P2_E_ACTION` | 0（真实传输同验） | `p2_rejects_unapproved_or_write_actions`、`p2_https_wrong_target_and_write_action_issue_zero_connections` |
| 证书不可信（真实 TLS） | `P2_E_TLS` | 0（握手失败） | `p2_https_untrusted_certificate_stops_before_http_request` |
| 主机名不匹配（真实 TLS） | `P2_E_HOST` | 0（握手失败） | `p2_https_hostname_mismatch_stops_before_http_request` |
| 服务端重定向（真实 TLS） | `P2_E_REDIRECT` | 源站 1、重定向目标 0 | `p2_https_redirect_is_not_followed_and_target_receives_zero_requests` |
| 响应含未授权字段（真实 TLS） | `P2_E_SCOPE` | 2（初始化 + 1 次读取后拒绝，无分页/重试） | `p2_https_response_with_unapproved_field_blocks_whole_page` |
| 未接线传输（无依据时的兜底） | `P2_E_PROTOCOL_PENDING` | 0 次发网 | `p2_unwired_https_transport_fails_before_sending` |

> 说明：请求侧范围越界为零请求；**响应侧**字段越界必然发生在一次请求之后，因此只承诺「整页拒绝、不返回、不落库、停止本次 P2、无后续分页或重试」。

## 4. 合法读取全链路

### 4.1 桩传输（守卫语义）

`p2_legal_read_runs_full_chain_with_scope_derived_args`：授权 `https://wps.example.test/mcp`、`file_id=dbsheet_replica_001`、表 3 字段 `{A,B,C}`、窗口、主体；结果 1 次初始化 + 1 次调用，`args` 由授权派生（含 `fields`）、不含 token，`attempts_used=1`。

### 4.2 真实 HTTPS 客户端（本机测试服务）

`p2_https_legal_read_runs_full_chain_with_trusted_ca`：reqwest 真实 TLS 连接本机 HTTPS 服务（`p2-local.test` 经测试解析映射到 `127.0.0.1`，私 CA 注入信任根），走完「预检 → 初始化 → 读取 → 字段校验 → 审计」，服务端记录 **2 次请求**（initialize + `tools/call`），返回记录仅授权字段，`attempts_used=1`。

## 5. TLS、重定向、会话与重试

- `P2TlsPolicy` 默认全严格；`.no_proxy()` 避免环境代理改写目标（本机实测曾被系统代理拦截，已固定关闭）。
- `classify_http_status`：3xx → `P2_E_REDIRECT`（不跟随）；401/403 → `P2_E_AUTH`；404 → `P2_E_SESSION`；429 → `P2_E_RATE`；5xx → `P2_E_SERVER`。
- `map_transport_error`：超时 → `P2_E_TIMEOUT`；错误链含 hostname/host name/dnsname → `P2_E_HOST`；含 certificate/tls/ssl → `P2_E_TLS`；其余 → `P2_E_PROTOCOL`。只归类，不回显原始文本。
- 读取预算见 §2；会话过期最多重建一次，重建消耗已发出的那一次预算。
- 审计行：`p2 action=dbsheet.list_records host=… file=dbsh…01 sheet=3 outcome=… attempts=…`，不含完整 `file_id` 与 token。

## 8. 真实 429 / 400006 的处理条款（拟批）

1. 若 A2 窗口内真实 429 未自然出现：P2 记「未观察，待专项验收」，**禁止刷请求触发**；不因此判定 P2 不通过，但必须写明未覆盖。
2. 400006（授权失效）如需主动演练：由签审人另批隔离账号与窗口；演练前明确「缺证是否阻塞 S0」；未另批则记「真实重授权未演练」。
3. 两类错误在代码侧均已映射（`P2_E_RATE` / `P2_E_AUTH`）且属于「停止本次读取」而非重试项之外的动作；真实响应文本仍不回显。
