## 1. 这个方案换掉了什么

首联目标从「业务副本的一小部分字段」换成「一张只有合成数据的表」。这样做的收益与代价都必须写清：

| 维度 | 换成合成专用表后 |
|---|---|
| 暴露面 | 首联读到的每一行都是人造值，**不含任何客户、金额、税号、电话等业务数据**；即使服务端未按 `fields` 裁剪，泄露的也只是合成串 |
| 协议验证 | 仍能完整验证端点、认证头、会话头、`notifications/initialized`、`tools/call` 响应形状、`DELETE` 终止、400006/429 等线协议行为 |
| Q1（服务端字段裁剪） | **已实测成立（2026-11-23）**：`fields=["code"]` 时响应只回 `code`；证据来自同一 MCP 工具的插件通道（§4.3） |
| Q2（单副本隔离） | **部分验证 + 不可证**——错误目标被网关拒绝（`400100`），但「只能读这一张」无法在单账号环境取得服务端证据；改由流程约束承担（见 §4.8） |
| C5（字段一致性） | **不解除**——合成表没有「业务字段跨页变化」这回事；C5 的真实副本验证继续待专项授权 |
| 投产判断 | 不构成「可以读生产台账」的依据；只构成「协议假设是否成立」的依据 |

一句话：**它把「协议能不能通」和「数据该不该给」拆开了**——前者可以先用合成表验证，后者仍需单副本/字段级授权依据。

## 4. 先做预检，再谈发网

1. 建表后，把 `file_id`/`sheet_id`/字段名与字段 ID 填进授权 JSON（模板见 `A2授权单-合成专用表.json`）。
2. 跑 `--check`（只预检、不发网、不建状态库、不消费 `grant_id`）：
   `cargo run -p voucher-cli --offline -- wps-p2-read --grant <json> --state <db> --check`
   预期输出 `"check":"preflight"` 且退出 0；任何一项不满足（字段空、端点非 https、`page_size` 不符、窗口超限）都应在这一步被拒。
3. 预检通过**不等于**可以执行：仍需 A2 签署后才允许发网一次（入口缺口见 §5.0）。

### 4.6 27 vs 50 的诊断（2026-11-23，本地 + 插件通道，零新增真实调用）

**现象**：第二发 CLI 收到 27 条，插件同表同参数收到 50 条。

**根因（已定位）**：SkillHub 的 `offset` 是**不透明字符串游标**，不是数字偏移。CLI 当时发的是 `"offset": 0`（数字），服务端按另一套语义处理，只回了首页一段。

证据（插件通道，同一合成表、`fields=["code"]`、`page_size=50`）：

| 调用 | 结果 |
|---|---|
| 首屏（`offset` 省略/空） | 50 条（`SYN-0001…0050`）+ 游标 `BF` |
| 下一页（`offset="BF"`） | 10 条（`SYN-0051…0060`），无后续游标 → 全表 60 行 |

**修复**：`P2ReadOnlyEntry` 构造 `arguments` 时改为 `"offset": ""`（首屏空串游标）；同时把响应里的 `data.detail.offset` 作为 `cursor` 带回并输出，便于下一次核对。

**回归**：新增本机 HTTPS 用例 `p2_https_wps_envelope_cursor_is_reported`——断言 `cursor == "VW"`，且服务端收到的读取请求体里是 `"offset":""`（不是数字 0）；`services::wps_p2` 40 例。

**残余不确定**：我们没保留第二发里「数字 0」那次的原始响应，无法 100% 证明 27 就是该语义造成的；但「字符串游标 → 50 条」已被同参数对照实测证实，CLI 侧参数已改成同一形状。要闭环，需要再签一发（`A2-SYN-20261123-04`）确认 CLI 也返回 50 条。

**结论**：CLI 与插件在相同参数下都返回 **50 条 + 游标 `BF`**，`27` 的成因（数字 `0` 被当作另一种游标语义）**实证闭环**；`DELETE` 第二次确认被真实端点接受。残余：`total` 仍为 `null`（游标分页不返回总数），如需总数只能靠翻页累计或另行确认。

### 4.8 Q2 目标校验探针（2026-11-23，插件通道，2 次合成目标）

用户决定「先做 403 对照、接受靠流程约束」。用同一 MCP 工具对**合成目标**做两次只读探针（不涉及任何业务数据）：

| 探针 | 请求 | 返回 |
|---|---|---|
| 篡改 `file_id`（末位 `D`→`E`，长度不变、不存在） | `dbsheet.list_records` | `{"code":400100,"message":"第三方服务错误：请求参数不支持"}` |
| 正确 `file_id` + `sheet_id=999`（不存在） | 同上 | `{"code":400100,"message":"第三方服务错误：Sheet not found"}` |

**能得出**：错误目标在网关层即被拒，**没有任何记录返回**；参数（文件、表）确实由服务端校验。
**不能得出**：权限隔离——`403000001`（权限不足）需要一个「**存在但未共享给该账号**」的文件，本账号个人云盘内无法制造；`400100` 是通用参数错误码，不区分「无权限」与「不存在」。
**判定**：Q2 记「**部分验证 + 不可证**」——服务端会校验目标并在参数层拒绝，但「主体只能读这一张表」无法在本环境取得服务端证据，风险由**流程约束**承担（2026-11-23 用户确认接受）：

1. 入口白名单：`file_id` 必须等于授权单批准值，否则 `P2_E_TARGET` 本地拒绝、零请求；
2. 单次授权 + 隔离状态库登记（`grant_id` 消费即不可重放）；
3. 执行窗口 ≤15 分钟、整场 ≤8 次、读取 ≤3 次、终止 ≤1 次；
4. 只批必要字段（这次只批 `["code"]`）；
5. 合成表未共享、账号单人使用（2026-11-23 用户核对）。

该判定与 §6「能得出 / 不能得出」表一致：Q2 不因本次探针升级为「已证」。

## 5. 执行步骤与停止条件（A2 签署后）

步骤：`initialize` → `notifications/initialized` → `tools/call dbsheet.list_records`（**首联只批 1 列：`fields=["code"]`**、`offset=0`、`page_size=50`）→（允许时）`DELETE`。

> 为什么先 1 列：这一发的主要目的是验证 Q1（服务端是否按 `fields` 裁剪）。只要 `fields` 批全 3 列就永远测不出来；先批 1 列，看响应里有没有 `amount`/`day` 即可判定。

**任一命中即停止，并保留脱敏证据**：

1. 响应不是 `result.content[].text` 的 JSON，或缺 `records` 数组；
2. 初始化未下发 `Mcp-Session-Id`（或 404 重建语义不一致）；
3. 返回字段超出本次批准集 `["code"]`（整页拒绝，`P2_E_SCOPE`）；
4. 出现任何非 `SYN-*`/非预期数值/非 2026-01 日期；
5. 401/403、400006、429（记录后停止，不重试、不刷请求）；
6. 执行窗口到期或整场请求预算耗尽（`P2_E_WINDOW`/`P2_E_EXEC_LIMIT`）；
7. `DELETE` 被拒（结果标「远端终止未确认，本地已关闭」，不再追加请求）；
8. 端点、主机名、证书与授权单不一致（本地即停，零请求）。
