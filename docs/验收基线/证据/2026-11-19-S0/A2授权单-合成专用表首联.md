## 1. 这个方案换掉了什么

首联目标从「业务副本的一小部分字段」换成「一张只有合成数据的表」。这样做的收益与代价都必须写清：

| 维度 | 换成合成专用表后 |
|---|---|
| 暴露面 | 首联读到的每一行都是人造值，**不含任何客户、金额、税号、电话等业务数据**；即使服务端未按 `fields` 裁剪，泄露的也只是合成串 |
| 协议验证 | 仍能完整验证端点、认证头、会话头、`notifications/initialized`、`tools/call` 响应形状、`DELETE` 终止、400006/429 等线协议行为 |
| Q1（服务端字段裁剪） | **仍不能证明**——合成表只有 3 列，无法区分「服务端按 fields 裁剪」与「本来就只有 3 列」 |
| Q2（单副本隔离） | **仍不能证明**——读通合成表不说明该主体是否还能读其他文件 |
| C5（字段一致性） | **不解除**——合成表没有「业务字段跨页变化」这回事；C5 的真实副本验证继续待专项授权 |
| 投产判断 | 不构成「可以读生产台账」的依据；只构成「协议假设是否成立」的依据 |

一句话：**它把「协议能不能通」和「数据该不该给」拆开了**——前者可以先用合成表验证，后者仍需单副本/字段级授权依据。

## 4. 先做预检，再谈发网

1. 建表后，把 `file_id`/`sheet_id`/字段名与字段 ID 填进授权 JSON（模板见 `A2授权单-合成专用表.json`）。
2. 跑 `--check`（只预检、不发网、不建状态库、不消费 `grant_id`）：
   `cargo run -p voucher-cli --offline -- wps-p2-read --grant <json> --state <db> --check`
   预期输出 `"check":"preflight"` 且退出 0；任何一项不满足（字段空、端点非 https、`page_size` 不符、窗口超限）都应在这一步被拒。
3. 预检通过**不等于**可以执行：仍需 A2 签署后才允许发网一次（入口缺口见 §5.0）。

### 4.1 本地预检实测（2026-11-23，零发网）

用模板的副本（端点改为回环 `p2-local.test`，其余字段同 §3）跑了三次 `--check`：

| 用例 | 结果 | 说明 |
|---|---|---|
| `approved_by = null` | `P2_E_NOT_APPROVED: 授权缺少签批人`，退出 1 | 未签批即拒，符合 T0「默认关闭」 |

| 补签批人 + 当前时间窗口 | `{"check":"preflight","grant_id":"A2-SYN-20261123-01","sheet_id":1,"page_size":50,"ok":true}`，退出 0 | 其余字段（3 列 `fields`、`page_size=50`、`max_total_requests=8`）均能通过预检 |
| 真实表标识（2026-11-23 建表后） | `approved_by=null` → `P2_E_NOT_APPROVED`，退出 1 | 用已回填 `file_id`/`sheet_id=2` 的模板复核，仍先被签批人拦下 |

### 4.2 执行入口缺口（本轮未解决，须在 A2 签署前定）

现有 `wps-p2-read` **只允许回环端点**（`P2_CLI_LOOPBACK_HOSTS = ["p2-local.test","localhost","127.0.0.1"]`），真实端点会被直接拒绝——这是有意的测试边界，不是遗漏。因此合成表首联目前**没有可对真实端点执行的入口**：

| 选项 | 代价 | 风险 |
|---|---|---|
| A. 给 CLI 增加受控的真实端点模式（须同时满足 `--s0-approved`、授权单 `approved_by` 非空、端点白名单来自签批文件） | 改 `crates/voucher-cli`，需重锁构建并重跑门禁 | 工具从此具备真实网络能力，S0 未签前属提前开闸 |
| B. 桌面接线（数据页加只读入口） | 改前端 + Tauri 命令，工作量更大 | 同上，且 UI 需走查 |
| C. 暂不实现，等 A2 签署后再按签批范围加 | 首联推迟 | 无代码风险 |

**建议 C**：A2 未签、S0 未过之前不新增真实网络能力；签批时把「执行入口形态」作为授权条款一并签（决策表 §8 第 8 条）。本文件因此只声明方案与规格，不声明「已可执行」。

## 5. 执行步骤与停止条件（A2 签署后）

步骤：`initialize` → `notifications/initialized` → `tools/call dbsheet.list_records`（`fields` 3 列、`offset=0`、`page_size=50`）→（允许时）`DELETE`。

**任一命中即停止，并保留脱敏证据**：

1. 响应不是 `result.content[].text` 的 JSON，或缺 `records` 数组；
2. 初始化未下发 `Mcp-Session-Id`（或 404 重建语义不一致）；
3. 返回字段超出 `["code","amount","day"]`（整页拒绝，`P2_E_SCOPE`）；
4. 出现任何非 `SYN-*`/非预期数值/非 2026-01 日期；
5. 401/403、400006、429（记录后停止，不重试、不刷请求）；
6. 执行窗口到期或整场请求预算耗尽（`P2_E_WINDOW`/`P2_E_EXEC_LIMIT`）；
7. `DELETE` 被拒（结果标「远端终止未确认，本地已关闭」，不再追加请求）；
8. 端点、主机名、证书与授权单不一致（本地即停，零请求）。

## 6. 首联能得出的结论

| 结论 | 可否从合成表首联得出 |
|---|---|
| 端点/认证/会话/`tools/call` 响应形状是否符合 MCP 假设 | ✅ 可以（这是本方案的主要目的） |
| `notifications/initialized` 是否被接受 | ✅ 可以（接受与否在响应/状态码上可见） |
| `DELETE` 是否被接受 | ✅ 可以 |
| 400006/429 的真实形态 | ⚠️ 仅在自然出现时可记录；禁止刷请求触发 |
| 服务端按 `fields` 裁剪（Q1） | ❌ 不能 |
| 授权主体只能读这一个文件（Q2） | ❌ 不能 |
| C5 字段一致性 | ❌ 不能，继续阻断写入 |
| 「可以读生产台账」 | ❌ 不能 |
