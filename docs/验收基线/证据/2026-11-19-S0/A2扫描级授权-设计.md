## 1. 为什么需要新形态

现有单页单（`A2授权单-真实副本-0x.json`）每次只允许「一次授权、一张表、一页」，预算 4 次请求。全量扫描需要「多表 × 多页」，用单页单签 22 页不可行，也无法在**同一次运行内**给出可比的两遍指纹。

因此需要「运行级（scan-run）授权」：一次签署覆盖一次完整运行，预算、窗口、表范围、停止条件全部写死，**运行结束即失效**。

- 读取语义：游标分页，首屏 `offset=""`，后续页用上一页响应游标；`page_size=50`；游标只允许来自上一页响应，出现回跳/重复/空页提前出现即停。

## 3. 预算模型（单逻辑会话）

| 层 | 上限 | 说明 |
|---|---|---|
| 会话动作 | 常态 3：`initialize` 1 + `notifications/initialized` 1 + `DELETE` 1；允许 **≤1 次重建**，重建时 `initialize` 再 +1、通知再 +1 → **最多 6** | 一次运行只有**一个逻辑会话**；重建后同时活跃会话 ≤1，旧会话须 `DELETE` 或视为失效；出现两个同时活跃的 Session-Id 即停 |
| 单页读取重试 | ≤3 次 `list_records`（含会话重建后的重发与超时；发网前扣减） | 重试只从「读取余额」扣 |
| 单表页数 | **锁死实测页数**：2/1/8/8/1/1/1（sheet 1/2/3/4/5/6/14） | 出现预期之外的新页即停并记 `drift`，不得静默多读 |
| 两遍读取 | 必达 **44 次**（22 页/遍 × 2）；硬上限 **74 次**（44 + 30 次重试余量） | 两遍都须覆盖同一表集与页集；任一遍缺页即 `P2_E_INCOMPLETE` |
| 全局请求 | **≤80 次** = 会话 ≤6 + 读取 ≤74 | 发网前扣减，触顶即停 |
| 窗口 | ≤15 分钟；授权单有效期 **≤3 日** | 每次发网前检查剩余时间；行数须为签批前 24h 内实测 |

- 预算优先级：`全局 80` > `读取 74` > `单页重试 3` > `单表页数（实测值）`。任一触顶即整场停止，不静默跳过。
- 若一次 429/5xx 让重试消耗过大，允许放弃重试直接停止，但**不得**为了凑满 44 次读取而绕过停止条件。

## 4. 一致性（两遍独立扫描）

| 项 | 拟议 |
|---|---|
| 第一遍 | 全表顺序读取，产出每表 `records`/字段集/`digest`（`c5-fingerprint` 口径：`record_id|规范化字段 JSON` 的 sha256） |
| 第二遍 | 重新从首屏开始读取（**不续跑**），同样产出指纹 |
| 判定 | 两遍 `combined` 与逐表 `digest` 全部相等 → 「同一运行内自洽」；任一不等 → 停止并标记 `inconsistent`；任一遍缺表/缺页 → `P2_E_INCOMPLETE` |
| 不做的 | 不持久化游标、不跨进程续跑、不用两遍指纹冒充 C5 的一致性证据 |
| 一致性声明 | `list_records` 无快照 token：本运行只能证明「两次读取结果相同」，**不能证明源端未被修改**，也**不能排除服务端两次返回同一缓存/快照** |

## 5. 停止条件（任一触发即整场停止并记录）

1. 任一请求返回非 2xx，且不属于已定义的「会话重建/可重试」情形；
2. 响应出现未授权字段（`P2_E_SCOPE`）；
3. 游标重复、页号回跳、`sheet_id` 不在 §2 清单（`P2_E_TARGET`）；
4. 单表出现实测页数之外的新页（`drift`）、任一遍缺页（`P2_E_INCOMPLETE`）、读取 >74、全局 >80、窗口耗尽；
5. 两遍指纹不一致；
6. 同一 `(sheet_id, record_id)` 在两次读取中字段集合或值不同（标 `inconsistent`）；
7. 凭据不可用/过期（`P2_E_AUTH`/`P2_E_CREDENTIALS`）；
8. 出现 GET/SSE 请求或第二个 `Mcp-Session-Id`。

## 6. 停止后的动作

- 停止后**不再发**任何读取、初始化、通知请求。
- 仅当停止原因**不属于**越权（`P2_E_SCOPE`/`P2_E_TARGET`）、认证（`P2_E_AUTH`）、凭据（`P2_E_CREDENTIALS`）、TLS（`P2_E_TLS`/`P2_E_HOST`），且窗口与全局预算仍有余额时，允许**一次** `DELETE`；否则立即本地关闭，并在结果中记 `Skipped(原因)`。
- 停止原因为 **429/限流**（HTTP 429 或服务端 400006）时，**不发 `DELETE`**，直接本地关闭并记 `Skipped(rate_limited)`。
- 无论是否发送 `DELETE`，运行状态一律标「已终止、未完成」，不得续跑。

## 7. 凭据与日志

- 凭据只从显式 `--token-file`（0600）读取一行，不进 argv、不进日志；用后 `fsync` + 删除文件 + 内存 drop，并记录「文件已不存在」的核对结果。
- 审计行只含：`sheet_id`、页号、行数、游标哈希前 8 位、动作计数、本地错误码；**不含记录值、不含完整游标、不含远端 message、不含 token**。
- 卷宗归档：`docs/验收基线/证据/2026-11-24-真实副本-扫描/`，含 run 摘要 JSON（动作计数、每表页数与行数、**两遍各自的逐表 `digest` 前 16 位与起止时刻**、两遍 `combined`、停止原因）、`create=0` 传输计数。
- **不归档**：状态库副本、游标原文、两次原始响应体。
- 证据模板首行固定：「本证据不构成 C5 ①②③，不解除写入阻断；两遍互比只排除两次读取间结果不同，不排除服务端返回同一缓存/快照」。

## 8. 重申请与失效

- 一次性运行：成功、失败或触发停止**均即失效**，`grant_id` 由 `p2_consumed` 永久标记消费。
- 重新取证须**新** `grant_id`，并附上次运行报告：停止原因、已取/未取页数、动作计数、是否发出 `DELETE`。
- 同一 `file_id` **30 日内 ≤1 次扫描运行**；字段集变更**不构成**新申请理由，重复申请须书面说明并附上次运行结论，由安全/运维复核。
- 窗口不延长；窗口内未完成的页面作废，不得以「续跑」名义跨窗口继续。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 一次运行读大量业务数据 | 暴露面扩大 | 7 表字段白名单 + 单副本 + 15 分钟窗口 + 结束即失效 |

| 两遍间源端变化 | 误判 | 指纹不一致即停并标 `inconsistent`；证据明写不等于 C5 |

| 真实 429/400006 自然出现 | 运行中断 | 记录并停止，不重试、不刷请求；400006 演练需另批 |

### 13.2 Q2 五条流程约束落码（2026-11-24 第二轮）

Q2「主体读权限能否限定唯一副本」在单账号环境不可取得服务端证据（`A2授权单-合成专用表首联.md` §4.8 已定：部分验证 + 不可证），故改由五条流程约束承担，本轮把它们从文档条文化为代码路径：

| # | 约束 | 落码位置 | 失败码 / 语义 | 用例 |
|---|---|---|---|---|
| ① | 入口白名单：目标必须是签批值 | `P2ScanSpec::validate`（`crates/voucher-core/src/services/wps_p2.rs:1553`）：`file_id != approved_file_id` 即拒；CLI 缺 `approved_file_id` 键时 `p2_scan_spec_from_value` 直接 `P2_E_GRANT`（`crates/voucher-cli/src/main.rs:509`） | `P2_E_TARGET` / `P2_E_GRANT`，零请求、不建库 | `scan_rejects_file_id_outside_approved_target`、`scan_grant_without_approved_file_id_is_refused` |
| ② | 单次授权 + 隔离状态库登记 | `P2ScanRun::run`：`P2Consumption::consume(grant_id, mask_id(file_id), window_end, now)` 整场一次（`SqliteP2State` 主键冲突 → `P2_E_ALREADY_USED`） | 重放被拒 | `scan_reads_two_passes_and_consumes_grant_once` |

落码时修掉的三个既有缺陷：

1. **扫描路径完全没有主体核对**：`P2ScanSpec` 只有 `grant_id/approved_by`，`run()` 直接 `consume` 后发网；单页单 `P2Grant::preflight` 有主体核对而扫描没有 → 扫描比单页单更宽。现补齐同源判定。
2. **`consume` 早于全部预检**：原顺序是 `validate → 窗口 → consume → 取 token → initialize`，主体/目标类本地可判错误若发生在 `consume` 之后就会白烧一次性授权。现顺序为 `validate → 窗口 → 主体 → bind 审计 → consume → token → initialize`。
3. **CLI 用签批人姓名冒充账号主体**：`wps_p2_scan` 原写 `FileTokenCredential{ subject: spec.approved_by.clone().into() }`，使「主体一致」恒真。现改为取 `approved_subject`（或本机 `--subject` 覆盖），并在 `--check` 与执行输出中把该格标为 `subject_state=declared-grant|declared-cli|missing` + `subject_note=主体为签批单/本机声明值，非服务端核对`——**不把自述当核对证据**。

证据边界（写进卷宗，不许升格）：本落码证明「入口侧把目标与主体钉死在签批值上」，**不**证明服务端只授予该文件读权限；`approved_subject` 目前只能由签批单/命令行自述，因为 token 文件（`/Users/apple/.dsh/dsh-wps.json`）只含 `token`/`expiresIn`/`tokenUpdatedAt` 三个键、无可核对的账号标识。故 Q2 仍记「部分验证 + 不可证」，S0-06 的「Q2 已解」不得据此成立。
