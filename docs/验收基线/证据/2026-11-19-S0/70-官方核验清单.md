## 1. 两个前置问题（不解决则 A2 不签）

### Q1：SkillHub 的 `dbsheet.list_records` 是否在**服务端**按 `fields` 裁剪？

- 为什么必须问：本地 `P2ReadOnlyEntry` 会丢弃未授权字段并整页拒绝，但这是**客户端事后防线**；若服务端仍回传整行，未授权字段已经离开 WPS 边界。
- 需要官方的答复形式：
  1. `list_records` 动作是否接受 `fields` 参数（本机插件 schema 有 `fields`，但插件参数≠服务端实现）；
  2. 该参数是否在**服务端**生效（响应体只含指定字段），还是仅客户端过滤；
  3. 字段标识用名称还是 ID，`prefer_id` 之类开关是否影响；
  4. 如不接受 `fields`，是否有等价的白名单机制（视图/受限字段集/只读投影账号）。
- 可接受的证据：官方文档中该 MCP 动作的参数与响应说明（含版本/日期），或官方工单/邮件答复（附工单号）；**本机插件 schema、WPS REST 文档、本地白名单均不算**。
- 提供人：安全/运维向 WPS 提交；开发整理问题原文与技术背景。

### Q2：能否把授权主体的**服务端读权限**限制到唯一非生产副本？

- 为什么必须问：`kso.dbsheet.read`（以及 MCP 侧授权 scope）是**接口级**权限，不等于文件级隔离；若同一主体对该账号下其他文件也有读权限，单副本隔离只在本地 `file_id` 白名单里成立。
- 需要官方的答复形式：
  1. MCP/SkillHub 授权是否支持只对指定文件（`file_id`）授权；
  2. 是否为该动作单独建只读主体（独立账号/应用），其可见文件能否收敛到 1 个副本；
  3. 共享/继承权限/共享链接是否会把其他文件带进该主体的可见范围；
  4. 若无法做到文件级隔离，是否有「合成专用表」这类可行替代（见 §4）。
- 可接受的证据：官方权限模型说明 + 实际配置界面的可复现步骤（截图/录屏可由签审人执行）；**插件参数、本地白名单不能替代**。
- 提供人：安全/运维；用户提供副本 `file_id` 与账号主体信息。

## 4. 退路：全合成专用表（需签审人批准才可提）

- 做法：由用户/业务方在 WPS 新建一张**只含批准字段**的合成表（无真实客户名、金额、税号），按同一 A2 授权单只读。
- 能证明什么：字段投影与只读链路在真实服务端可用；**不能证明**业务副本的字段一致性（C5 仍阻断）。
- 不能做什么：不得拿业务副本直接试；不得因为合成表通过就把 C5 降级。
- 决策人：安全/运维 + 用户；采用时需在 A2 授权单 §1 注明「合成专用表」并给出表 ID。
