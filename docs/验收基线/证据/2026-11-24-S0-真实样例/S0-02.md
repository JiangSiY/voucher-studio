# S0-02 凭据读取路径（真实运行样例）

- 执行时刻：2026-11-24T05:40Z（北京时间 13:40）
- 授权：取证授权单第 2 项（运行应用自带的「凭据状态」读操作一次，记录 `token_set`/`token_expires_at` 两个字段；不导出 token）
- 素材：`target/release/bundle/macos/Voucher Studio.app`（本轮 `npm run tauri build` 产物，`BUILD_EXIT=0`，同时产出 `Voucher Studio_0.25.0_aarch64.dmg`）
- 安全前置：启动前对真实库做过快照 `backups/pre-s0-20261124T054024Z.db`（2,281,472 B）与 `pre-s0-wal-…bin`（4,157,112 B）

## 实际发生

启动后应用立即请求读取钥匙串条目 `VoucherStudio`，macOS 弹出系统授权对话：

> **Voucher Studio** 想要使用你储存在钥匙串的「**VoucherStudio**」中的机密信息。若要给予许可，请输入「登录」钥匙串的密码。
> ［始终允许］［拒绝］［允许］

截图：[S0-02-钥匙串授权对话.png](./S0-02-钥匙串授权对话.png)（已裁切到对话区域，未包含其它窗口内容）

**没有输入密码、没有点「允许」**：助手端的辅助访问权限此前已被系统拒绝（`osascript -10004`），无法点击系统对话；即便可点，也不应由代执行方输入机主钥匙串密码。随后终止进程（`kill`），应用退出，未取得任何凭据内容。

## 结论：**已证（OS 强制授权，不可静默读取）/ 未证（`token_set` 与 `expires` 字段值）**

- 已证：应用读取钥匙串**必须经 macOS 授权对话**，未授权时读不到；也就是说「凭据被静默读取」这条风险在本机真实存在过测试——**没有发生**。这是 S0-02 想要的核心安全性质。
- 未证：`token_set` / `token_expires_at` 两个界面返回值（本次读取就没成功，自然没有值），以及真实 WPS token 的读取链路（条目本就不存在，见 [S0-01](./S0-01.md)）。
- 顺带观察：本次启动**未改动业务库**——启动前后 `voucher.db` 仍为 2,281,472 B、`voucher.db-wal` 仍是 2026-11-24 08:08 的那份 4,157,112 B。

## 需要签审人做的一件事（如果要继续补这一格）

在本人面前启动该应用、在系统对话里输入登录钥匙串密码并点「允许/始终允许」一次，再记录界面上的 `token_set`/`token_expires_at`。这一步只有机主能做，助手不代输密码。
