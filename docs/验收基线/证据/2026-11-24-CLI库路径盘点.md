## 关键事实

- `CoreContext::init`（`crates/voucher-core/src/lib.rs:80`）三步都会留痕：`AppPaths::resolve` 只解析、`paths.ensure_all()`（`crates/voucher-core/src/utils/paths.rs:63`）建 8 个目录、`db::connection::open`（`crates/voucher-core/src/db/connection.rs`）建库并设 WAL、随后跑迁移。因此守卫必须在 `CoreContext::init` **之前**。
- `AppPaths::resolve`（`crates/voucher-core/src/utils/paths.rs:39`）是纯函数；`db_file()` = `<base>/voucher.db`。CLI 侧新增的 `existing_db_path()` 只调用这两者，不建任何东西。
- 桌面端（`src-tauri`）与其它 crate 仍走 `CoreContext::init`，语义未改；守卫只存在于 CLI。

## 拒绝分支的零副作用证据

`crates/voucher-cli/tests/db_path_guard.rs`：

- `read_only_commands_refuse_a_missing_db_without_creating_dirs`：`list-pending` / `c5-fingerprint` 对不存在库 → exit 1，且上两级目录运行后仍不存在（证明没 `ensure_all`）。
- `import_ledger_refuses_a_missing_db_and_creates_nothing`：`import-ledger` 对不存在库 → exit 1，stderr 含「写命令不会隐式建库」「不存在」「既有初始化路径」，目录未生成。
- `list_pending_still_reads_an_existing_database`：既有库 → exit 0、输出空数组（回归）。
- `import_ledger_output_carries_the_database_path`：`--dry-run` 输出含 `database`，等于 `<data-dir>/voucher.db` 的绝对路径。
- `c5_fingerprint_output_carries_the_database_path`：JSON 含 `database` 与 `records`。

## 残留风险（未在本轮解除）

- `restore --target` 若被指向真实生产目录，会覆盖该目录的 `voucher.db`；这是命令本意，未加二次确认。
- `wps-p2-read` / `wps-p2-scan` 的 `--state` 指向何处由调用者负责；P2 状态库与生产库不同文件，但没有「禁止指向生产目录」的硬校验。
- `--data-dir` 指向一个**存在但为空**的目录时，只读命令会按「库不存在」exit 1；写命令同样 exit 1，需要先跑桌面端或 `restore` 初始化。
