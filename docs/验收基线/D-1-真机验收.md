| # | 验证项 | 通过标准 | 结果 | 证据 |
|---|--------|---------|------|------|
| D1-1 | first_thumb_for_vouchers 正常路径 | 当前页 6 张凭证的 6 条首附件都返回 | ✅ | `enhance_e2e::first_thumb_for_vouchers_returns_enhanced_path_when_present` |
| D1-2 | 空输入短路 | `voucher_ids = []` → 返回 `Vec::new()` 且不触达 SQL | ✅ | `enhance_e2e::first_thumb_for_vouchers_handles_empty_input` |
| D1-3 | 无附件凭证不出现 | 凭证没附件 → 不在结果中（前端按 missing 显示占位） | ✅ | `enhance_e2e::first_thumb_for_vouchers_omits_voucher_without_attachment` |
| D1-4 | N+1 消除 | list_vouchers 在 items 非空时**只**对当前页 ids 跑一次 IN-query | ✅ | `commands::mod.rs::list_vouchers` 一次性 `first_thumb_for_vouchers(conn, &ids)`；`if items.is_empty()` 短路 |
| D1-5 | VoucherListResult.thumbs 字段 | 前端拿到 `Record<voucherId, VoucherThumb>` | ✅ | `commands::mod.rs::VoucherListResult { items, total, thumbs }` + camelCase 序列化 |

**核心 SQL**（一次性 IN-query，按 `MIN(id)` 取每张凭证的首附件）：

```sql
SELECT a.voucher_id, a.file_path, a.enhanced_path, a.enhanced_source
FROM attachments a
INNER JOIN (
    SELECT voucher_id, MIN(id) AS min_id
    FROM attachments
    WHERE voucher_id IN (?,?,?,...)
    GROUP BY voucher_id
) m ON m.voucher_id = a.voucher_id AND m.min_id = a.id
```

### 5.3 关键观察

1. **列表页「扫/截」角标**与数据库 `enhanced_source` 字段 1:1 对位：
   - scan_01 / 03 / 05 → 「扫」（紫色渐变）
   - scan_02 / 04 / 06 → 「截」（暗底）
2. **编辑页与列表页状态独立**：在 scan_06 编辑页把切换器拨到「原图」后，回到列表，列表缩略图依然显示增强版——这是预期的「per-attachment 状态只在编辑页生效」行为（列表页始终展示增强版以供快速识别）。
3. **暗色主题适配**：缩略图卡片边框用 `var(--stroke)`、角标用半透明背景，在 dark / light 主题下均无对比度问题。
4. **无 N+1 性能回退**：单页 6 张凭证只跑 1 次 `first_thumb_for_vouchers`（`if items.is_empty()` 短路；非空才拼 IN 占位符），相比 N 次 `list_by_voucher` 减少 5 次 SQL 往返。

## 7. 已知限制 / 后续可改进

- **D-1 仅限「首附件」**：当前 `first_thumb_for_vouchers` 按 `MIN(id)` 取首附件，假设一图一凭证（v0.6 已固化）。多图场景留待 D-x。
- **缓存策略未变**：缩略图直接走 `convertFileSrc` 暴露本地文件，未做内存级缓存。WebView 自带资源缓存对单页 6 张足够；超过 50 张/页时再考虑 `URL.createObjectURL(blob)` 或 service worker。
- **大图原始尺寸下载**：列表页 img 标签只声明 `width:100% height:100% object-fit:cover`，未指定 `srcset/sizes`；如果未来单图 >2 MB 可考虑补一份 200×260 的纯缩略图副本（独立 JPEG 写到 `attachments/<hash>.thumb.jpg`）。
