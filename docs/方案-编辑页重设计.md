## 3. 审计（按你给的三条标准）

### 3.1 方便操作
- **主操作在表单下方**（`VoucherEditor.vue:461-473`），而右栏顶部还有翻张/展开按钮；改完字段要下滚才能保存。
- **「建立关联 / 新建组」与展开区混在一起**：展开后除了「取消」没有收束感，按钮不在同一行（截图 2）。
- **视觉权重不分层**：换图 / 重跑识别 / 裁剪（破坏性、低频）与核心字段编辑（高频）同级同色。

### 3.2 便于填写修改
- 表单第一行是**只读的凭证编号**，白占一行；而"状态"（核对流程最常改，⌘⇧Enter 就改它）排在第 6 行。
- 三个高频字段（日期 / 金额 / 状态）分散在第 2、5、6 行，视线来回跳。
- 备注固定 `rows="3"`：短备注留白、长备注要滚（`VoucherEditor.vue:455-457`）。
- 「● 未保存」提示在底部操作行，右栏上半部看不到当前是否有未保存改动。

### 3.3 便于查看
- 图片是"看"的主体，却被 8 行表单 + 识别结果 + 历史 + 两个无样式区块淹没。
- 识别结果没有"已填/未填"的汇总，看不出还有哪些字段可填。
- 修改历史没有条数与最近时间摘要，折叠后无从判断要不要展开。

## 4. 重设计方案

### 4.1 区块顺序 v2

| 新顺序 | 区块 | 默认状态 |
|---|---|---|
| 1 | 头部：编号 + 翻张 + **保存状态点**（● 未保存 / 已保存）+ 展开 | 常显（`sticky`） |
| 2 | **附件 / 图片**（操作收成一行：图标 + 文字） | 常显 |
| 3 | **核心字段**：摘要 → **日期 + 金额（并排半宽）** → 状态 → 对方 → 标签 → 备注 | 常显 |
| 4 | **关系与组**：相关凭证 + 所属事项组（**上移到识别结果之前**——你的第一条要求） | 常显 |
| 5 | **识别结果**（标题带「识别到 N 项 · M 项可填」） | **折叠** |
| 6 | **修改历史**（标题带「N 条 · 最近 <时间>」） | **折叠** |
| 7 | 底部操作条：还原 / 保存 / 保存并下一张 | 常显（B 批可吸底） |
| 8 | 最后修改 | 常显 |

### 4.2 折叠规范
- 新增统一组件 `CollapsiblePanel.vue`：`fluent-panel` + 标题行右侧 chevron 按钮；`aria-expanded` / `aria-controls`；**`Esc` 收起**；标题左侧可放徽标。
- 默认折叠：识别结果、修改历史；默认展开：附件、核心字段、关系与组。
- 折叠状态：会话内记忆（是否落 localStorage 见 §9 选项 3）。

### 4.3 操作按钮排布规范（**同一行**）
- 每个区块**头部右侧只放一个主按钮**（「＋ 建立关联」「＋ 新建组」「全部填入」…）。
- 展开后的输入行也是**一行**：`[类型 ▾] [搜索凭证…] [搜索] [说明（可选）…] [建立] [取消]`；窄栏（<320px）允许折成两段，但**按钮始终成组相邻**。
- 统一控件高 32px、间距 8px（`var(--s-2)`）、主按钮右端对齐；`Esc` = 取消。
- 关系区块补齐样式：与识别结果/历史同款 panel 外观；列表项单行三段式「类型标签 + 对方编号·日期·金额 + 说明」+ 行尾图标按钮「解除」。

### 4.4 表单区改进（便于填写）
- 移除只读「凭证编号」行（编号已在头部显示）。
- 高频三件套前置：**日期 + 金额并排（各半宽）**，**状态**紧随其后（可选分段按钮，见 §9 选项 2）。
- 摘要保留在首位（`DescriptionInput` 带模板）；
- 备注高度自适应（2–6 行）或固定 2 行 + 可拖拽（§9 选项 4）。
- 「● 未保存」移到头部，与编号同排。

### 4.5 视觉一致性
- 关系 / 组 / 识别结果 / 历史统一 `fluent-panel`；区块间距统一 `var(--s-3)`；标签字号统一 `--type-caption`。
- 新样式一律 scoped 写在组件内；只用现有令牌（`--s-*` / `--label-*` / `--radius-panel`），不引新颜色。

## 10. 追加方案（2026-10-17，用户提出）：图片与字段左右并排 + 标签移到输入框上方

### 10.1 用户原话与理解

> 「将凭证图片组件和字段编辑左右并排显示，字段编辑的字段标签放在对应的编辑框上方，
> 取消日期、金额和对方账户、收支方向的并排显示，这个设计方案是否可行」

即：① 右栏里**图片在左、字段在右**；② 字段标签从"左侧一列"改成"**在输入框上方**"；
③ 既然标签在上了，就**取消**日期/金额、对方账户/收支方向这两组并排。

### 10.2 可行性结论：**可行，但只能在小宽度之外的那一档做并排**

横向空间是硬约束（数字来自现有 CSS）：

| 档位 | 右栏可用宽度（`.split` / `.split--wide`，`src/pages/LibraryPage.vue:860-862`） |
|---|---|
| 常规 | `minmax(320px, 1fr)` → 约 **320–420px** |
| 展宽（⌘⇧E） | `minmax(560px, 1.6fr)` → 约 **560–900px** |

- **常规档拆两列不可行**：320–420px 分给图片与字段各约 160–210px。
  图片列 160–210px 配 200px 高的图（`.att-card .att-img { height: 200px }`，`src/styles/base.css:1242`）已经偏小；
  字段列 160–210px 放"标签在上 + 输入框"勉强，但日期原生控件约需 130px、收支方向三段按钮要三个字宽，
  再加右侧滚动条 → **会很挤**，反而回到"控件挤在一起"的老问题。
- **展宽档拆两列可行**：560–900px 分列后各 **280–450px**。标签移到上方后字段列不再需要标签列宽，
  280px 对"标签在上 + 全宽输入"是舒服的；图片列 280px 配 200px 高的图也正常。
  **前提**：把展宽档的右栏下限从 560px 抬到约 **720px**（`minmax(720px, 2fr)`），否则窗口不够宽时两列都会缩到 250px 以下。
- **常规档保持上下堆叠**（图片在上、字段在下），并排只在展宽档生效——这与现有 `dense`（`!wide`）开关天然对应。

### 10.3 标签移到输入框上方：可行，而且**顺带消灭一整类对齐 bug**

- 现在"左侧一列标签"的难点在于**对齐**：`voucherEditorLayout.test.ts` 专门锁死
  `.editor-form { grid-template-columns: max-content minmax(0,1fr) }` + `.ed-row { display: contents }`
  （起因是 2026-09-28 用户截图报"输入框左边缘参差不齐"）。
- 标签移到上方后，所有输入框**同起点、同宽**，这类错位从结构上不可能发生 →
  **该契约应改写**（不是删除纪律，而是换成新的结构契约：`.field { display: grid; gap: 4px }` +
  标签必须紧邻其输入框 + 不得再出现左侧标签列）。这条要显式记进开发日志：**旧契约因设计变更而退休，新契约取而代之**。
- 行高变化（如实说明）：一行的输入框仍是 `--control-h-md` 32px，但多了标签行 → 约 **54px/行**
  （标签 13px 字 ≈18px + 间距 4px + 输入 32px）。7 个字段从约 272px 变成约 380–420px。
  **常规档会变高约 150px**（右栏本来就要滚，但滚动变长）；展宽档因为字段在右、图在左，总高度反而更短。

### 10.4 取消两组并排：与"标签在上"是自洽的

标签在输入框上方时，并排会让"标签 → 输入"的对应关系变模糊（两个标签、两个框，谁配谁要靠位置猜）。
取消后每个字段独占一行、全宽显示，**字段内不再出现小字子标签**（10.3 的旧规则连同 `.ed-pair-*` 一并退休）。

### 10.5 新方案（两选一）

| | A. 严格按你说的 | B. 展宽档字段区两列（省高度） |
|---|---|---|
| 布局 | 展宽档：`[图片 \| 字段]`；常规档：图片在上、字段在下 | 同 A，但展宽档的**字段区内部**再分两列（日期/金额、对方账户/收支方向） |
| 高度 | 字段区约 380–420px（比现在高约 150px） | 字段区约 270–300px |
| 与你的话 | 完全一致（并排取消） | 只把"并排"挪到字段区内部，仍需你点头 |
| 风险 | 常规档滚动变长 | 窄一点的展宽窗口会回到"控件挤" |

**建议 A**（你的原话），B 作为后续可选项——因为"标签在上"的价值就是"每个字段一行、看得清"。
